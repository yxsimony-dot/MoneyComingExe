## Context

见 `proposal.md`。当前 `EntryStrategySettings` 已承载最小入场K线浮动和入场线百分比，并由图表生命周期与全盘盈亏复盘共同使用。首轮和第二轮通过同一个方向反应范围函数寻找最终合格K线，但该函数当前只收到从本轮触发K线开始的搜索数组，无法检查触发前的反向动能。

现有设置面板已经具备整数步进、字段级持久化迁移和统一实时刷新流程；“五分钟K线识别”小型信息按钮也已经存在。自动化Electron和打包EXE测试必须在窗口首次显示前置于所有显示器矩形之外。

## Goals / Non-Goals

**Goals:**

- 在不改变实体和影线判定顺序的前提下，为最终候选增加可复用的反向动能过滤。
- 让首轮与第二轮既能回看触发前历史，又保持各自红框从本轮触发K线开始。
- 让设置面板、图表、盈亏复盘和规则说明共享同一个当前参数。
- 以字段级迁移兼容已经保存的旧版策略设置。

**Non-Goals:**

- 不改变60分钟突破、回调触发或二次触发规则。
- 不改变最小实体浮动、方向侧影线2倍/3倍分段或入场线百分比公式。
- 不把触发前历史纳入红框、计划线或本轮可见生命周期。
- 不增加第三轮、参数预设、恢复默认按钮或新的独立规则大按钮。

## Decisions

### 1. 在现有策略设置对象中增加独立整数参数

在 `EntryStrategySettings` 中增加语义明确的字段，例如：

```ts
interface EntryStrategySettings {
  reactionBodyTicks: number;
  entryRangePercent: number;
  oppositeCandleCount: number;
}
```

同时增加最小值0、最大值10和默认值6。领域层继续严格验证有限整数和范围，渲染层只提交有效整数。相比把0解释为一个特殊的可空字段，保留明确整数可以让持久化、DOM状态、测试夹具和复盘调用保持单一类型。

### 2. 候选先通过实体和影线，再检查反向动能

搜索顺序固定为：

1. 判断候选方向及实体是否达到当前tick阈值。
2. 计算方向侧影线；达到实体3倍时按既有规则跳过。
3. 对实体和影线已经合格的候选向前统计连续反向K线。
4. 数量达到参数时跳过并继续搜索，否则确定为最终方向反应K线及其定价模式。

这样不会对原本连“实体候选”都不构成的K线做额外分类，也不会改变2倍至3倍风险侧入场语义。参数为0时直接绕过第3步，避免把“达到0根”误判成所有候选都应过滤。

### 3. 使用完整历史上下文和独立搜索起点

方向反应搜索需要同时知道：

- 可向前读取的完整有序5分钟历史上下文；
- 本轮触发K线在上下文中的搜索起点；
- 本轮允许搜索到的生命周期终点。

领域入口将通过索引或等价的显式上下文传递实现，而不是把触发前K线拼进本轮 `analysisBars`。首轮候选可读取首轮触发之前的数据；第二轮候选可读取二次触发之前的数据，包括首轮期间已经存在的K线。触发前历史只服务于候选过滤，本轮风险侧极值仍从本轮触发索引统计到最终候选索引。

相比在渲染层预先计算一个布尔值，领域层统一读取历史能确保图表、复盘、首轮和第二轮使用完全相同的口径。

### 4. 反向序列使用三态扫描

从候选前一根开始逆序扫描：

- 反方向实体：计数加一，达到N即可停止并过滤。
- 十字星，即 `close === open`：跳过，不计数也不中断。
- 同方向实体：立即停止，候选不因更早K线而被过滤。

扫描到数据起点仍不足N时接受候选。该算法最多只需找到10根反向K线或第一根同方向K线；即使夹有十字星，实际数据规模下也无需额外缓存。价格方向直接使用开收盘比较，不使用tick容差，保持与现有K线方向判断一致。

### 5. 被反向动能过滤的候选继续参与风险侧极值

最终红框仍对“本轮触发K线至最终合格反应K线”的完整区间求风险侧极值。因此因反向数量过滤、3倍影线过滤或实体不足而经过的搜索K线都不会从极值数组中删除。盈利侧边界仍只取最终合格反应K线。用于向前统计但位于本轮触发前的K线绝不进入该区间。

### 6. 沿用现有版本化存储键进行字段级迁移

继续使用当前策略设置存储对象和键，为缺失或无效的 `oppositeCandleCount` 单独回退到6，然后把完整规范化对象写回。旧版存储天然缺少该字段，因此不需要清除用户已有的最小浮动和入场线百分比，也不需要建立第二份互相覆盖的设置键。

### 7. 在现有面板和统一刷新流中接入参数

“连续反向K线数量”作为第三个紧凑步进控件加入当前设置控制区，使用0至10边界和1步长。有效变化按现有顺序执行：保存设置、保持当前选择重算生命周期、重算全盘盈亏摘要、刷新已打开的盈亏窗口。

“五分钟K线识别”继续复用现有小型信息按钮和对话框，在动态文字中增加当前参数与三态扫描规则，不新增占用工具栏空间的大按钮。

### 8. 测试覆盖领域边界和离屏GUI行为

领域测试覆盖多空镜像、正好达到阈值、超过阈值、少一根、0关闭、十字星透明、同方向中断、跨触发点回看、触发前历史不进入红框以及两轮一致性。复盘测试验证参数改变会改变交易集合且与生命周期一致。

设置GUI测试覆盖0和10边界、默认6、旧存储迁移、无效输入、重启保留、摘要及已打开盈亏窗口刷新、动态规则说明和紧凑布局。所有Electron测试通过 `tests/electron-test-launch.mjs` 的 `launchElectronTest()` 启动；直接EXE验收追加 `--test-window-offscreen` 并验证窗口与所有显示器无面积交集。

## Risks / Trade-offs

- [生命周期函数只传入触发后数组，导致无法正确跨触发点回看] -> 将历史上下文与本轮搜索起点显式分离，并增加首轮首根候选和第二轮首根候选测试。
- [触发前K线误入红框，扩大风险范围] -> 红框只对本轮搜索切片求极值，使用明显更低或更高的触发前测试数据验证隔离。
- [旧本地设置缺少新字段导致所有参数一起回退] -> 继续字段级规范化，只修复缺失或无效的新字段。
- [每次参数变化进行全量复盘可能产生短暂阻塞] -> 复用现有统一刷新和单次复盘结果，不增加第二次并行计算；只有有效整数变化才刷新。
- [设置面板增加第三个控件后窄窗口拥挤] -> 使用现有稳定尺寸和换行布局，并通过离屏桌面窄视口截图检查无重叠。

## Migration Plan

1. 扩展策略设置类型、默认值和字段级校验，使旧调用先通过默认6运行。
2. 改造方向反应搜索的历史上下文传递和过滤算法，补齐首轮、第二轮及红框边界测试。
3. 接入设置面板、持久化迁移和统一实时刷新，补齐盈亏复盘与GUI测试。
4. 更新应用内及外部规则文字，运行类型检查、相关单元测试、完整测试和构建。
5. 打包后按项目离屏窗口规范验收最新版EXE。

回滚时可移除新控件和过滤步骤，并让领域调用恢复到不传新字段的旧行为；持久化对象中多出的字段可被旧版字段级读取忽略，不涉及行情或交易数据迁移。
