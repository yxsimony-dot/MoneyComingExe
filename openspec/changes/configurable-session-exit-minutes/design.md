## Context

见 `proposal.md`。当前 `EntryStrategySettings` 已统一承载最小入场K线浮动、入场线百分比和连续反向K线数量，当前选中图表生命周期与全盘盈亏复盘共享该对象。休市策略仍由 `ENTRY_SESSION_POLICIES` 固定保存14:45/22:45入场截止和14:40/22:40强制离场K线起点，因此渲染层无法只修改一个参数就得到一致结果。

现有生命周期已经区分自然交易时段边界、数据提前结束、未入场结束和实际出场，并在强制离场K线内使用1分钟证据优先、5分钟保守回退。设置面板已经具备版本化本地存储、字段级迁移和统一实时刷新入口。自动化Electron与打包EXE测试必须在窗口首次显示前置于全部显示器矩形之外。

## Goals / Non-Goals

**Goals:**

- 从自然休市边界和当前设置统一派生入场截止、强制离场K线及图表终点。
- 让15分钟保持当前结果，让5至30分钟只改变时间参数而不改变事件优先级。
- 将0分钟实现为明确的“关闭休市离场”，并区分自然休市未完成与数据提前中断。
- 沿用当前设置对象、字段级持久化和统一复盘刷新流程。

**Non-Goals:**

- 不允许跨日盘、夜盘或交易日期继续持仓。
- 不修改止盈、止损、风险侧调整、第二轮触发、杠杆、手数或手续费规则。
- 不增加任意分钟输入、1分钟步进、每个品种独立设置、恢复默认按钮或参数历史。
- 不在软件中显示后台1分钟K线。

## Decisions

### 1. 在共享策略设置中增加有限选项字段

`EntryStrategySettings` 增加 `sessionExitMinutes`，有效值只允许：

```ts
const SESSION_EXIT_MINUTE_OPTIONS = [0, 5, 10, 15, 20, 25, 30] as const;
```

默认值为15。领域校验使用选项集合而不是单纯的0至30范围，防止12之类的值绕过5分钟粒度。现有生命周期和复盘继续只接收完整设置对象，避免图表使用新时刻而复盘仍使用固定时刻。

### 2. 静态时段策略只保存自然边界，动态派生退出计划

日盘15:00、夜盘23:00及对应交易分钟索引继续作为静态时段信息。每次构造生命周期时，根据 `sessionExitMinutes` 派生：

```text
sessionEnd = 自然休市边界

当 N > 0:
  entryCutoff = sessionEnd - N 分钟
  forcedExitBarStart = entryCutoff - 5 分钟

当 N = 0:
  entryCutoff = sessionEnd
  forcedExitBar = 无
```

真正入场仍以5分钟K线开始时间判断 `bar.start < entryCutoff`。因此非零值允许在以截止时刻结束的K线内入场并在同一根K线完成事件判断；0允许自然休市前最后一根5分钟K线入场。相比为每个选项维护一张固定时间表，分钟运算能减少日夜盘分支重复，并让测试直接验证公式。

### 3. 0分钟使用独立的自然休市未完成终止原因

生命周期终止原因增加语义明确的值，例如 `open-position-session-end`。满足以下条件时使用它：

- 当前参数为0；
- 已经发生真正入场；
- 已处理完自然休市前最后一根完整5分钟K线；
- 没有止盈或止损结果。

该状态不生成 `EntryExitSignal`，因此复盘自然进入未完成交易集合，最终资金不发生变化。它与 `data-end` 分开，可避免把完整覆盖到休市的数据误报成行情缺失，也方便图表和诊断说明真实原因。

### 4. 非零参数保持现有强制离场事件顺序

动态找到的强制离场K线继续进入现有退出分析。领域层先按完整1分钟证据或5分钟保守回退判断入场后止损、风险侧调整和止盈；只有仍处于持仓状态且整根强制离场K线完整存在时，才以其收盘价生成 `session-close`。

若数据在动态强制离场K线完成前中断，不补造收盘价或出场结果，生命周期仍使用 `data-end`。参数变化只改变被选中的K线，不改变价格触碰优先级。

### 5. 图表线段使用同一个生命周期终点

非零参数下，实际止盈、止损或休市出场仍决定线段终点。0分钟且自然休市仍持仓时，生命周期分析范围包含最后一根完整5分钟K线，所有适用线段绘制到该根并终止，不创建“休市出场”标记。

点击60分钟信号后的初始5分钟定位仍使用现有紧凑 `focusBars`，参数造成生命周期变长时不自动把全部K线纳入视口，避免压扁K线。

### 6. 参数控件使用有限选项下拉菜单

在现有三个紧凑参数组旁增加“休市前离场”选择框。选项显示为：

```text
0 分钟（关闭）
5 分钟
10 分钟
15 分钟
20 分钟
25 分钟
30 分钟
```

有限选项使用下拉菜单比可编辑数字输入更能阻止非法粒度。面板仍由“周一8根标记”控制可见性；隐藏面板不改变设置。窄窗口沿用现有换行布局并保持选择框稳定宽度。

### 7. 沿用现有存储键进行字段级迁移

加载设置时单独规范化 `sessionExitMinutes`：字段缺失、不为有限整数或不在选项集合时回退15，其他三个有效字段保持原值，然后将完整对象写回当前存储键。这样旧版本升级不会丢失用户已经调整的其他策略参数，也不需要维护第二份迁移键。

### 8. 有效变化复用统一策略刷新

选择变化后按现有顺序：

1. 验证并保存完整策略设置。
2. 更新控件和页面诊断状态。
3. 保持当前选择与缩放，重新计算选中事件的首轮和第二轮生命周期并替换图表元素。
4. 使用同一设置执行一次全盘盈亏复盘并更新参数面板摘要。
5. 若“盈亏情况”已打开，复用同一结果刷新完整内容。

不为休市参数建立独立的局部图表修补逻辑，因为动态截止可能改变入场资格、第二轮机会、出场类型和后续资金曲线。

### 9. 规则和测试覆盖动态边界

应用内完整入场规则与外部规则文档改用“当前休市前离场分钟数N”描述，并保留15分钟示例，同时补充0、5和30分钟的边界示例。

领域测试覆盖日夜盘全部七个选项、截止时刻前后、强制离场K线内入场、止盈止损优先、数据不完整、0分钟最后一根K线入场、自然休市未完成和不跨时段。复盘测试验证完成/未完成交易、休市出场次数、最终资金及统计同步变化。GUI测试覆盖默认值、旧设置迁移、重启保留、实时刷新和窄窗口布局，并遵守项目离屏窗口规范。

## Risks / Trade-offs

- [0分钟允许最后一根K线入场后立即到达自然休市，容易被误认为应按收盘价平仓] -> 使用独立终止原因、无退出信号和明确规则文字，测试断言不产生 `session-close`。
- [分钟索引与北京时间换算出现一根K线偏差] -> 从自然边界统一反推截止与强制离场K线，并为日夜盘5、15、30分钟分别断言具体K线区间。
- [旧存储对象缺少字段导致其他策略参数被重置] -> 按字段规范化，只对新字段回退15并写回完整对象。
- [参数变化引起全量复盘短暂阻塞] -> 只在实际选项变化时刷新，复用一次复盘结果，不额外执行第二次计算。
- [设置面板增加第四组控件后窄窗口拥挤] -> 使用下拉菜单和现有换行布局，通过离屏窄视口截图验证无重叠。

## Migration Plan

1. 扩展共享策略设置、默认值、选项校验和生命周期终止原因，使旧调用先以15分钟运行。
2. 将静态时段政策改为从自然边界派生动态截止和强制离场K线，并补齐领域测试。
3. 接入复盘未完成交易与统计，验证0和非零值的资金结果。
4. 增加设置控件、字段级持久化及统一实时刷新，补齐GUI测试。
5. 更新应用内及外部规则，运行类型检查、相关测试、完整测试和构建。
6. 打包后按项目离屏窗口规范验收最新版EXE。

回滚时可隐藏新控件并在领域入口固定传入15；存储对象中的额外字段可被旧版字段级读取忽略，不涉及行情或交易数据迁移。
