## Context

动机见 `proposal.md`，可验收行为见 `specs/five-minute-take-profit-line/spec.md`。

现有领域层通过 `entryReactionRange()` 返回首次方向反应红框，通过 `entryQuarterSignal()` 返回白色入场价和第一根真正入场K线，通过 `entryStopLossSignal()` 返回黄色计划止损价。5分钟渲染选择状态保存这些结构化结果，并使用独立折线序列显示白线和止损线；两者从红框左边界延伸至原观察窗口末尾，并通过空的自动缩放结果避免压扁K线。

新止盈计划既依赖红框价格范围，也依赖真正入场是否存在。默认止盈线在红框形成后立即出现，但风险侧触碰只能从真正入场K线本身开始检测。用户已明确同一根真正入场K线同时触碰白线和风险侧边界时直接调整止盈，不根据5分钟OHLC推断根内价格顺序。

## Goals / Non-Goals

**Goals:**

- 使用领域纯函数计算落在tick网格上的多空镜像默认止盈价和调整后止盈价。
- 在原观察窗口内，从真正入场K线本身开始确定第一次风险侧触碰。
- 使用亮蓝色阶梯线准确表达默认目标和调整目标的时间边界。
- 使用单一“触底”或“触顶”标记说明止盈目标发生变化的原因。
- 通过诊断状态、领域测试和Electron验收覆盖公式、搜索起点、同根触碰、线条边界和清理生命周期。

**Non-Goals:**

- 不判断K线是否实际触碰默认或调整后的止盈价。
- 不生成止盈成交、离场标记、仓位、盈亏、风险收益比或交易统计。
- 不改变真正入场搜索、白色入场价、黄色止损价、红框算法或60分钟分析。
- 不从风险侧触碰K线后延长或重开观察窗口。
- 不增加止盈倍数、颜色、观察根数或tick的用户配置。

## Decisions

### 1. 使用独立的结构化止盈计划

领域层新增独立的止盈结果，不把字段加入白色入场信号或黄色止损信号。建议结构为：

```text
EntryTakeProfitSignal:
  direction
  tick
  rangeTicks
  targetTicks
  defaultPrice
  adjustedPrice
  lineStartBar
  entryBar?
  riskTouchBar?
```

计算函数接收首次方向反应范围、原观察窗口和现有四分之一入场信号。红框存在时始终返回默认止盈计划；`entryBar` 不存在时不扫描触碰，`riskTouchBar` 保持为空。

独立结构能够清楚区分“真正入场信号”和“入场后止盈计划”，也为未来实际止盈触发保留明确边界。把止盈字段塞入 `EntryQuarterSignal` 会让入场定位与离场计划互相耦合，因此不采用。

### 2. 使用整数tick计算两倍红框高度

止盈价格沿用共享的 `MARKET_PRICE_TICK`，先把红框高度换算为整数tick：

```text
rangeTicks = round((high - low) / tick)
targetTicks = rangeTicks * 2
distance = targetTicks * tick

longDefault = high + distance
shortDefault = low - distance
longAdjusted = high
shortAdjusted = low
```

对于最低价3020、最高价3031和tick为1的红框，`rangeTicks` 为11，`targetTicks` 为22，因此多头默认止盈为3053，空头默认止盈为2998。两倍整数tick不需要额外向上取整；最终价格仍按tick网格归一，避免非1 tick时出现浮点尾差。

直接使用价格小数 `(high - low) * 2` 虽然当前tick为1时结果相同，但会绕开现有整数tick约束，不利于未来支持其他标的，因此不采用。

### 3. 风险侧搜索复用真正入场结果并包含入场K线

计算函数通过四分之一信号的 `entryBar` 在原观察窗口中定位搜索起点，并扫描从该索引到数组末尾的K线：

```text
longTouch  = bar.low <= range.low
shortTouch = bar.high >= range.high
```

第一次满足条件后立即返回，不继续收集重复触碰。真正入场之前的K线不参与判断；没有真正入场时完全不扫描。

若真正入场K线本身满足风险侧条件，则直接把它作为第一次触碰。5分钟OHLC无法还原同一根K线内先触碰白线还是先触碰风险侧边界，用户已明确接受不判断根内顺序并立即调整止盈。

备选方案是从真正入场K线的下一根开始搜索。该方案会与已确认的“从真正入场K线开始”规则冲突，因此不采用。

### 4. 使用独立亮蓝色阶梯折线序列

5分钟图新增止盈折线序列，使用 `#4fc3f7`、2像素实线和阶梯线型。线条数据从红框左边界对应的 `lineStartBar` 开始覆盖到原观察窗口最后一根实际K线：

```text
触碰K线之前 -> defaultPrice
触碰K线及之后 -> adjustedPrice
```

没有真正入场或真正入场后没有风险侧触碰时，所有点使用 `defaultPrice`，因此显示为水平线。存在触碰时使用图表库现有的阶梯线型表达垂直切换，并让切换位置与 `riskTouchBar` 对齐。

止盈序列使用与白线、止损线一致的自动缩放隔离策略，不向右侧价格轴提供自动范围。默认止盈价可能暂时位于当前视口之外，但用户可以通过既有价格轴交互查看真实位置。

拆成两条水平线能够形成类似效果，但会增加序列和清理状态，并更难保持切换处连续，因此采用单一阶梯序列。

### 5. 风险侧触碰使用单一方向标记

第一次风险侧触碰使用稳定ID并加入现有5分钟K线标记集合：

```text
多头 -> K线下方、亮蓝色“触底”
空头 -> K线上方、亮蓝色“触顶”
```

该标记说明止盈目标为何发生调整，不表示止损、止盈或离场。真正入场K线同时触碰风险侧时，真正入场标记和触底或触顶标记允许并存；渲染时使用不同文字、尺寸或纵向位置避免互相遮挡。

后续重复触碰不生成额外标记。把每次触碰都标出会让图面变得拥挤，并模糊“第一次触碰导致目标变化”的因果关系，因此不采用。

### 6. 诊断和清理沿用现有选择生命周期

5分钟图诊断属性增加止盈信号是否存在、方向、tick、区间tick数、目标tick数、默认价、调整价、真正入场时间、第一次风险侧触碰时间、线条首尾时间、首尾索引、点数、颜色、线型和自动缩放状态。

普通 `linked` 选择、无红框、切换入场事件、切换数据集、回到最新和清除选择时，同时清空止盈序列、触底或触顶标记及诊断属性。新增结果只属于5分钟渲染选择，不写回 `WeeklyEntry`，也不改变现有白线或止损信号。

### 7. 规则文件和内置回退文本保持一致

外部 `futures_investigation_20261009/entry-rules.md` 与内置 `src/shared/entry-rules.ts` 同步追加止盈规则，明确以下顺序：

```text
首次方向反应红框形成
  -> 立即显示默认止盈线
  -> 白线首次触碰产生真正入场
  -> 从真正入场K线本身开始检测风险侧
  -> 首次触底或触顶后切换到调整止盈价
```

文档同时给出3020至3031的多空示例，并明确亮蓝色线与触底、触顶标记只表示计划变化，不表示已经止盈离场。

## Risks / Trade-offs

- [同一根入场K线内无法判断白线与风险侧边界的先后] -> 按已确认规则将整根入场K线纳入检测，并在规则中明确不推断根内顺序。
- [默认止盈价远离K线导致线条默认不可见] -> 保持真实价格且隔离自动缩放，允许用户通过既有价格轴查看，避免再次压扁K线。
- [阶梯切换在触碰K线时间坐标附近造成视觉歧义] -> 用同根“触底”或“触顶”标记固定事件归属，并用诊断索引验证切换点。
- [真正入场标记与风险侧标记出现在同一根K线] -> 使用不同文字和布局，并加入同根场景的窄窗口视觉验收。
- [规则文件与内置文字漂移] -> 增加一致性测试，检查公式、示例、颜色、检测起点和非目标声明。

## Migration Plan

本变更不迁移行情数据或用户配置。实施时先增加止盈领域结果、纯函数和单元测试，再扩展5分钟选择状态、亮蓝色阶梯序列、风险侧标记、诊断与清理逻辑，随后更新规则文件和Electron验收。

完成后运行单元测试、类型检查、生产构建、应用冒烟测试和Windows目录包构建，并在多头、空头、无真正入场、入场同根触碰、后续首次触碰、重复触碰、无触碰、数据末尾不足和目标价位于视口外的场景下验收。

回退时移除止盈计算、亮蓝色阶梯序列、触底或触顶标记、诊断属性和新增规则段落；现有红框、白色入场线、黄色止损线、真正入场标记、60分钟事件和行情数据不受影响。
