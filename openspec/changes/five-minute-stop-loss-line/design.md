## Context

动机见 `proposal.md`，可验收行为见 `specs/five-minute-stop-loss-line/spec.md`。

现有领域层通过 `entryReactionRange()` 返回首次方向反应红框的方向、最高价、最低价、反应K线和前置极值K线，并通过 `entryQuarterSignal()` 计算白色入场线。5分钟渲染状态同时保存红框和四分之一入场信号；白线使用独立折线序列，从红框左边界延伸到原观察窗口末尾，并通过空的自动缩放结果避免压扁K线。

止损价格同样只依赖红框和共享的 `MARKET_PRICE_TICK`，但位于红框之外。用户已明确选择保持当前K线自动缩放比例，即止损线可能暂时位于可视价格范围之外，需通过既有右侧价格轴交互查看。

## Goals / Non-Goals

**Goals:**

- 使用领域纯函数计算落在tick网格上的多空镜像止损价格。
- 让止损线与现有红框、白线和5分钟选择状态共用时间边界与生命周期。
- 使用与红色上涨K线、绿色下跌K线、绿色动态回调线、红框和白线清楚区分的明黄色实线。
- 通过单元测试、诊断属性和Electron测试验证公式、边界、颜色、清理和自动缩放隔离。

**Non-Goals:**

- 不搜索或标记价格首次触碰止损线的K线。
- 不生成止损成交、离场事件、盈亏、仓位或风险收益比。
- 不定义或显示止盈规则。
- 不改变白色入场价格、真正入场搜索、观察窗口长度或60分钟入场分析。
- 不为止损线增加开关、比例、颜色或tick配置。

## Decisions

### 1. 使用整数tick计算75%止损距离

领域层新增独立的结构化止损结果和纯函数，输入首次方向反应范围与正数tick：

```text
rangeTicks = round((high - low) / tick)
stopTicks = ceil(rangeTicks * 3 / 4)
distance = stopTicks * tick

longStop = low - distance
shortStop = high + distance
```

先把红框总高度换算为整数tick，再对距离执行向上取整，能够避免二进制浮点误差，也能保证多空使用同一个距离。对于最低价3020、最高价3031和tick为1的区间，`rangeTicks` 为11、`stopTicks` 为9，因此多头止损为3011、空头止损为3040。

建议结果结构为：

```text
EntryStopLossSignal:
  direction
  price
  tick
  rangeTicks
  stopTicks
  lineStartBar
```

`lineStartBar` 复用红框的 `extremeBar`。止损信号不保存触发K线，因为本次不判断实际止损。

备选方案是直接计算价格小数后对最终多头价格向下取整、空头价格向上取整。该方案把止损方向与tick取整耦合，容易在非1 tick时产生不对称结果，因此不采用。

### 2. 止损计算与四分之一入场计算保持独立

新增止损纯函数而不把止损字段塞入 `EntryQuarterSignal`。两者虽然共享红框和tick，但生命周期语义不同：白线负责搜索真正入场，止损线只描述计划风险边界。独立结果便于后续增加止损触发或止盈规则时维持清晰边界，也能单独测试本次不搜索离场K线。

渲染层在 `highlightEntry()` 中由同一个 `reactionRange` 分别计算四分之一入场信号和止损信号，并写入同一个5分钟 `entry` 选择状态。没有红框时两者均不存在。

备选方案是建立一个包含入场、止损和未来止盈的综合交易计划对象。当前止盈尚未定义，提前建立综合对象会固化未知字段，因此暂不采用。

### 3. 使用独立明黄色折线序列

5分钟图新增独立止损折线序列，使用明黄色 `#f4c95d`、2像素宽实线、整数价格格式，并隐藏最后值标签、价格线和十字光标圆点。数据点从 `lineStartBar` 开始，按同一止损价格覆盖到观察窗口最后一根实际K线。

独立序列不会替换绿色动态回调线、白色入场线、红框或K线标记。线条在红框形成后立即写入，即使没有真正入场K线也持续显示到原窗口末尾。

备选颜色包括红色和绿色。红色会与上涨K线及红框重叠，绿色会与下跌K线及动态回调线重叠，因此采用明黄色。

### 4. 止损线不参与价格轴自动缩放

止损折线序列使用与白线一致的自动缩放隔离策略，不向右侧价格轴提供自动范围。这样选择事件后不会因为红框外的止损价扩大纵向区间并压扁K线。

这一选择意味着止损线可能落在当前可视价格范围之外。系统仍将真实止损价格和完整线段数据写入序列；用户可使用现有右侧价格轴拖动、缩放和复位交互查看。测试应区分“序列已正确绘制在真实价格”与“当前屏幕坐标内可见”，不得为了截图强制扩大自动范围。

备选方案是让止损线参与自动缩放，能够保证默认可见，但会改变用户已确认需要保持的K线比例，因此不采用。

### 5. 诊断和清理沿用现有选择生命周期

5分钟图诊断属性新增止损信号是否存在、方向、价格、tick、区间tick数、止损tick数、线条首尾时间、首尾索引、点数、颜色、线型和自动缩放状态。Electron测试通过这些属性验证真实数据结果，即使线条当前在视口之外也能验收其价格与时间边界。

普通 `linked` 选择、无红框、切换入场事件、切换数据集、回到最新和清除选择时，同时清空止损序列及诊断属性。新增状态只属于5分钟渲染选择，不写回 `WeeklyEntry`。

### 6. 规则文件和内置回退文本保持同一口径

外部 `futures_investigation_20261009/entry-rules.md` 与内置 `src/shared/entry-rules.ts` 同步追加止损规则。文档使用与领域函数相同的整数tick公式和3020至3031示例，并明确以下顺序：

```text
首次方向反应红框形成
  -> 同时得到白色四分之一入场线
  -> 同时得到明黄色75%止损线
  -> 后续首次触碰白线才是真正入场
```

黄色线是预先计算的计划止损边界，不表示已发生离场；止盈和实际止损触发均不在本次范围内。

## Risks / Trade-offs

- [止损价可能位于当前可视价格范围之外] -> 保留真实价格序列和诊断值，允许用户通过既有价格轴交互查看，并在规则中说明该行为。
- [整数tick换算遇到不在tick网格上的脏数据] -> 使用最接近整数的range tick数，保留原始K线不变，并通过诊断属性暴露计算值。
- [黄色线与其他标记在局部位置重叠] -> 使用独立2像素实线、无点标记和高对比黄色，并进行桌面及窄窗口截图验收。
- [后续实际止损规则误用本次计划线] -> 领域结果不包含触发K线，规则和测试明确本次不产生离场事件。
- [规则文件与内置回退文字漂移] -> 增加一致性测试，检查公式、示例、颜色和非目标声明。

## Migration Plan

本变更不迁移行情数据或用户配置。实施时先增加止损领域结果、纯函数和单元测试，再扩展5分钟选择状态、黄色线序列、诊断与清理逻辑，随后更新规则文件和Electron验收。

完成后运行单元测试、类型检查、生产构建、应用冒烟测试和Windows目录包构建，并在多头、空头、整除、非整除、无真正入场、数据末尾不足、快速切换和止损价位于视口外的场景下验收。

回退时移除止损计算、黄色折线序列、诊断属性和新增规则段落；现有红框、白色入场线、真正入场标记、动态回调线、60分钟事件和行情数据不受影响。
