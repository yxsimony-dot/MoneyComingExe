## Context

动机见 `proposal.md`，可验收行为见 `specs/five-minute-first-reaction-range/spec.md`。

现有领域层已经能够通过 `entryObservationWindow()` 从真实触发K线开始取得最多16根连续5分钟K线，并通过 `entryObservationLine()`生成对应方向的动态回调线。渲染层使用带类型的 `ChartSelection` 保存普通联动或入场观察状态，5分钟图也已有独立于图表画布的悬浮区间 DOM 覆盖层。

首次反应范围同时依赖方向、K线实体方向、前置极值所在K线和价格坐标。它应作为观察窗口的派生结果计算，不能重新执行60分钟入场分析，也不能改变既有触发记录、动态回调线或观察窗口长度。

## Goals / Non-Goals

**Goals:**

- 用可独立测试的纯函数生成多头或空头首次反应范围。
- 让范围结果同时保存反应K线、前置极值K线、价格边界和方向，避免渲染层重复推导。
- 在5分钟图中绘制随时间轴、价格轴和窗口尺寸稳定更新的红色范围框。
- 将范围定义同步到外部规则文件和程序内置回退规则。

**Non-Goals:**

- 不修改 `analyzeWeeklyEntries()`、60分钟突破与回调判定或入场事件数量。
- 不改变“触发根 + 后续15根”的观察窗口、5分钟动态回调线和现有方向标记。
- 不把首次反应范围用于自动生成新的入场、止损、止盈或离场信号。
- 不增加范围颜色、线宽、观察根数或搜索方向的用户配置。

## Decisions

### 1. 领域层使用纯函数返回结构化首次反应范围

在 `src/domain/weekly-entry.ts` 中新增纯函数，输入入场方向和已经截取的观察窗口，成功时返回类似结构：

```text
EntryReactionRange:
  direction
  reactionBar
  extremeBar
  high
  low
```

多头从数组首根开始查找第一根 `close > open` 的K线，空头查找第一根 `close < open` 的K线，`close === open` 继续向后搜索。未找到时返回空结果，不接受窗口外数据。

极值搜索使用从触发K线开始、截至并包含首次反应K线的全部记录：多头取最低 `low`，空头取最高 `high`。因此首次反应K线自己的下影线或上影线也参与范围计算；若它产生新的极值，极值K线与反应K线相同，红框只覆盖该反应K线。若相同极值在范围记录中多次出现，按时间顺序保留第一次出现的K线，使横向起点稳定且结果可复现。

备选方案是在渲染层直接扫描K线。该方案会把业务规则分散到坐标绘制代码中，难以独立验证多空镜像和边界条件，因此不采用。

### 2. 范围随入场选择状态保存，不成为新的入场事件

`highlightEntry()` 在接收观察窗口时调用首次反应纯函数，并把可选范围结果保存在 `entry` 类型的5分钟选择状态中。普通 `linked` 状态不计算范围。范围结果只引用观察窗口内已有K线，不写回 `WeeklyEntry`，也不参与60分钟标记生成。

选择诊断数据增加范围是否存在、方向、起止K线、反应K线及上下价格边界，供 Electron 自动化测试读取。数据集切换、回到最新、普通联动选择和空观察窗口继续通过统一选择生命周期清空范围。

备选方案是把范围写入 `WeeklyEntry`。首次反应需要入场之后的最多15根数据，属于右侧观察派生信息；写进入场事件会混淆因果入场结果和事后观察结果，因此不采用。

### 3. 使用独立 DOM 覆盖层绘制红框

5分钟图创建独立的 `.entry-reaction-range` 覆盖层，与 `.linked-hover-range` 并存且均设置 `pointer-events: none`。红框使用清晰的红色边框和轻微透明底色，不创建新的图表序列，避免范围边界参与自动价格缩放或影响K线数据。

横向坐标按现有悬浮覆盖层方法，将 `extremeBar` 和 `reactionBar` 的逻辑索引转换为K线中心坐标，再各扩展半个实际柱间距，从而覆盖极值K线起点到反应K线结束。纵向坐标通过蜡烛序列的价格坐标换算取得 `high` 与 `low` 的屏幕位置，并限制在主价格窗格的可见区域内。完全离开视口时隐藏，部分离开视口时裁切显示。

当极值K线和反应K线相同，左右各扩展半个柱间距，保证红框只覆盖该根K线。图形的时间跨度不延伸到反应K线之后的观察记录。

备选方案是使用额外折线或自定义图表 primitive。折线无法自然表达封闭区域；primitive 会引入更多图表库耦合，而现有 DOM 覆盖层已验证能跟随逻辑坐标，因此采用 DOM 方案。

### 4. 通过统一调度保持范围框与视口同步

范围框采用 `requestAnimationFrame` 合并重绘。以下入口调度重绘：

- 入场选择或图表数据变化；
- 可见逻辑范围变化；
- 鼠标滚轮、水平拖动和价格轴拖动过程；
- 价格轴双击或工具栏恢复自动范围；
- 图表宿主尺寸变化；
- 动态回调线数据更新后。

每次渲染都重新读取逻辑坐标、价格坐标、时间轴宽度和主价格窗格高度，不复用旧像素值。隐藏或清除选择时取消待执行帧，并移除可测试诊断属性，避免旧框在快速切换时短暂出现。

备选方案是只在选择发生时绘制一次。该方案在用户缩放、平移或调整价格轴后会产生明显错位，因此不采用。

### 5. 规则说明同时更新外部文件和内置回退文字

在 `futures_investigation_20261009/entry-rules.md` 中增加5分钟观察窗口、动态回调线及首次反应范围定义，并同步 `src/shared/entry-rules.ts` 的默认文本。两处使用同一措辞，明确该范围是“价格触及回调区域后形成的第一次方向性反应范围，为后续继续迭代入场条件提供基础”，且当前不直接生成新信号。

外部规则文件继续是打包时复制到 `data/entry-rules.md` 的来源；内置文本只在外部文件不可用时作为回退。测试比较两处关键规则，避免开发态与打包态说明分叉。

## Risks / Trade-offs

- [价格轴拖动期间 DOM 框更新晚于图表一帧] -> 使用动画帧合并高频事件，并在每一帧从图表API重新读取价格坐标。
- [范围框覆盖K线后降低可读性] -> 使用醒目边框配合低透明度底色，并保持 `pointer-events: none`，不遮断图表交互。
- [相同极值出现多次会产生多个合理横向起点] -> 固定选择按时间顺序第一次出现的位置，保证结果确定。
- [观察窗口跨交易时段时横向视觉间隔较大] -> 沿用真实5分钟数据逻辑索引，不补造休市K线，也不改变观察窗口规则。
- [图形状态与选择状态快速切换时残留] -> 范围生命周期绑定单一 `ChartSelection`，清除选择时同步隐藏覆盖层并取消待执行重绘。
- [后续入场规则可能改变范围用途] -> 本次只输出结构化范围和可视化，不把用途写死到自动信号判断中。

## Migration Plan

本变更不迁移行情数据、用户配置或入场事件。实施顺序为先增加纯函数和领域测试，再扩展5分钟选择状态与红框覆盖层，随后更新规则说明和 Electron 自动化测试。

完成后运行单元测试、类型检查、构建、应用冒烟测试和 Windows 目录包构建，并在多头、空头、触发根即反应根、无反应以及图表缩放场景下进行视觉验收。

回退时可移除首次反应纯函数、选择状态字段和 DOM 覆盖层；现有观察窗口、动态回调线、60分钟入场分析及数据文件均不受影响。
