## Context

动机见 `proposal.md`，可验收行为见 `specs/five-minute-entry-observation-window/spec.md`。

当前入场分析由 `src/domain/weekly-entry.ts` 生成 `WeeklyEntry`，其中已经保存60分钟所属K线 `bar`、真实5分钟触发记录 `triggerBar`、方向和回调线证据。该对象足以构造新的右侧观察窗口，无需重新执行任何入场判断。

当前 `src/renderer/main.ts` 的 `selectBar()` 对所有60分钟点击统一调用 `childrenFor()`，然后把整组子K线传给右侧 `highlight()`。`MarketChart` 仅保存 `selectedBars: Bar[]`，`drawMarkers()` 对这些记录统一绘制黄色方块，因此普通跨周期选择和入场观察暂时无法表达不同语义。

已有悬浮高亮和点击缩放同步依赖完整的60分钟子区间。本变更必须保留这些能力，并仅对带入场事件的明确点击进行分流。

## Goals / Non-Goals

**Goals:**

- 从既有 `WeeklyEntry.triggerBar` 稳定构造最多16根连续5分钟K线。
- 在渲染状态中明确区分普通子区间选择与入场观察窗口。
- 让具体入场标记点击、多事件默认选择、方向样式和数据末尾行为可预测、可测试。
- 复用现有点击缩放逻辑，同时保证完整观察窗口可见。

**Non-Goals:**

- 不修改 `analyzeWeeklyEntries()`、回调线公式、突破顺序或触发条件。
- 不改变60分钟图上的入场、突破、周一前8根和异常标记。
- 不改变60分钟悬浮时右侧完整子区间高亮。
- 不增加可配置的观察根数；本次固定为第一根加后续15根。
- 不把观察窗口解释为自动下单、持仓周期或退出信号。

## Decisions

### 1. 观察窗口由纯函数按全局5分钟序列切片

新增纯函数接收目标 `triggerBar`、完整5分钟数组和固定后续数量15。函数通过触发开始时间定位真实索引，并返回：

```text
start = indexOf(triggerBar.startMs)
end   = min(start + 16, bars5.length)
window = bars5[start...end)
```

触发记录不存在于当前数据集时返回空数组，不使用最近时间替代，也不构造虚拟K线。使用全局序列而不是原60分钟 `children`，才能自然跨越小时、时段和日期边界。

备选方案是在 `WeeklyEntry` 中提前保存16根记录。该方案会把纯展示窗口写入领域分析结果，并需要在数据截断时重复管理派生数据，因此不采用。

### 2. 右侧图表使用带类型的选择状态

将右侧当前仅有的 `selectedBars` 语义扩展为带类型的选择状态，例如：

```text
linked:
  bars

entry:
  bars
  triggerStart
  direction
```

普通 `linked` 状态继续绘制黄色方块。`entry` 状态把第一根绘制为醒目的方向标记，把其余记录绘制为较小、较弱的同方向方块。选择详情仍聚焦第一根触发K线。

选择状态和悬浮覆盖层继续相互独立。数据集切换、回到最新和显式清空选择时，两种选择状态都沿用现有生命周期清除。

备选方案是继续复用 `selectedBars` 并根据颜色参数临时分支。该方案无法可靠保存触发索引和方向，也会让后续重绘丢失语义，因此不采用。

### 3. 60分钟点击先解析入场事件再选择展示模式

60分钟点击处理接收当前图表事件中的 `hoveredObjectId`：

1. 若对象ID匹配某个入场标记，选择该标记对应的 `WeeklyEntry`。
2. 否则读取该60分钟K线的全部入场事件，并按 `triggerBar.startMs` 升序选择最早事件。
3. 找到事件时构造入场观察窗口，并传给右侧入场高亮方法。
4. 没有事件时沿用当前 `childrenFor()` 和普通黄色高亮。

标记ID继续包含方向与触发时间，可作为事件的稳定关联键。点击5分钟K线、日期跳转、异常定位和程序化双图定位继续使用普通选择路径，避免这些入口意外变成入场观察窗口。

备选方案是同一60分钟内同时叠加全部事件窗口。窗口可能重叠且方向相反，单根5分钟K线将产生含糊的颜色和聚焦目标，因此本次采用“具体标记优先、否则最早事件”的确定性规则。

### 4. 缩放定位以观察窗口而非原小时子区间为目标

带入场事件的60分钟点击仍在操作前读取左图当前可见逻辑跨度，但传给 `focusBars()` 的目标改为观察窗口。这样现有的“源跨度与目标最小跨度取较大值”规则会自动保证最多16根K线和边距完整可见。

普通60分钟点击继续把原小时子区间传给 `focusBars()`，不改变已完成的缩放同步行为。观察窗口为空时不移动右图，并沿用联动不完整提示。

### 5. 领域回归与交互验收分层验证

领域测试继续断言同一输入下 `analyzeWeeklyEntries()` 的完整结果未改变。新增纯函数测试覆盖：

- 正常返回16根；
- 跨60分钟、跨日期仍按数组连续取值；
- 数据末尾截断；
- 找不到触发记录时返回空；
- 后续K线不执行价格过滤。

Electron/Playwright 测试覆盖：

- 点击多头和空头信号后右侧标记数量、首根方向和弱化后续标记；
- 点击具体入场标记与点击含多个事件的K线本体；
- 普通60分钟K线仍显示全部黄色子K线；
- 悬浮覆盖层仍对应完整小时；
- 观察窗口完整可见且缩放跨度遵守现有规则；
- 切换标的和回到最新后观察状态被清除；
- 左侧入场标记计数与变更前基线一致。

## Risks / Trade-offs

- [用户点击K线本体时无法表达同小时内想查看的后一个事件] -> 允许点击具体多/空标记精确选择，并用最早事件作为可预测默认值。
- [入场窗口跨越休市后视觉上时间间隔较大] -> 按真实数据序列而非墙上时钟补齐15根，不生成休市K线。
- [普通黄色选择与方向窗口状态切换后残留旧标记] -> 由单一带类型选择状态统一生成全量 markers，每次切换完整重绘。
- [触发记录因数据切换不在当前5分钟数组中] -> 返回空窗口并保持右图当前位置，不按近似时间错误匹配。
- [方向颜色与已有60分钟箭头混淆] -> 保持同方向色系，但在右图使用“强触发标记 + 弱方块序列”，不复制左图完整文字箭头样式。

## Migration Plan

本变更不迁移数据或配置。实施顺序为先增加纯函数和测试，再引入带类型选择状态，最后连接60分钟点击分流并扩展端到端测试。完成后运行类型检查、单元测试、应用构建和 Electron 冒烟测试。

回退时可移除入场观察选择分支并恢复所有60分钟点击统一调用 `childrenFor()`；领域入场数据、CSV和用户配置不受影响。
