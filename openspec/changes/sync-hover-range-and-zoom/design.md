## Context

动机与用户行为见 `proposal.md`，可验收要求见 `specs/linked-chart-interaction/spec.md`。

当前双周期联动集中在 `src/renderer/main.ts` 的 `MarketChart` 和 `selectBar()` 中。`childrenFor()` 已按父K线真实起止区间返回5分钟子记录，点击后的黄色方块标记也已正确应用；本变更不修改这套映射规则。

当前问题来自两个实现限制：

- 60分钟图的十字光标移动只把右图光标同步到第一根5分钟子记录，没有保存或绘制完整子区间。
- `MarketChart.focus()` 固定使用120根K线宽度，未读取60分钟图当前的可见逻辑范围。

项目使用 Lightweight Charts 5.2.1。现有版本提供 `getVisibleLogicalRange()`、`setVisibleLogicalRange()`、`logicalToCoordinate()`、`subscribeVisibleLogicalRangeChange()` 和价格窗格 `getHeight()`，足以在不增加依赖的情况下实现本变更。

## Goals / Non-Goals

**Goals:**

- 将60分钟悬浮目标转换为右图可见、连续且只覆盖价格窗格的5分钟区间高亮。
- 保持悬浮态与点击选中态分离，避免临时浏览改变持久选择。
- 点击60分钟K线时，以左图当前可见逻辑跨度决定右图缩放，并完整容纳全部5分钟子记录。
- 对缩放、拖动、窗格高度和容器尺寸变化作出稳定更新。

**Non-Goals:**

- 不在悬浮时自动滚动或缩放右图。
- 不建立持续的双向缩放绑定；同步只发生在点击60分钟K线的定位动作中。
- 不改变5分钟点击60分钟父区间、日期定位、回到最新或标的切换的现有缩放规则。
- 不改变K线聚合、区间映射、选择标记和异常标记算法。

## Decisions

### 1. 使用价格主图上方的DOM覆盖层绘制悬浮区间

在5分钟图的 `.chart-container` 中增加一个默认隐藏、`pointer-events: none` 的绝对定位覆盖层。覆盖层使用低透明度冷色背景和清晰边框，视觉上区别于点击选中使用的黄色方块。

覆盖层状态由5分钟 `MarketChart` 保存，包括当前悬浮对应的首尾5分钟记录。点击选择仍继续使用 `selectedBars` 和 series markers，两种状态互不写入。

选择DOM覆盖层而不是 Lightweight Charts pane primitive，原因是本需求只需要矩形区间，现有页面已经在同一容器中用绝对定位管理窗格标签；DOM方案改动更小，也便于自动化测试检查显示状态和尺寸。

备选方案是实现 pane primitive 并直接在canvas绘制。它能更贴近图表渲染管线，但需要额外的primitive生命周期、渲染器和坐标状态，当前收益不足以抵消复杂度。

### 2. 以首尾逻辑索引计算高亮边界

继续调用 `childrenFor(parent, bars5)` 获取真实子区间。5分钟图根据首尾记录在自身 `bars` 中的逻辑索引计算覆盖范围：

```text
left  = logicalToCoordinate(firstIndex - 0.5)
right = logicalToCoordinate(lastIndex + 0.5)
top   = 0
height = panes()[0].getHeight()
```

半个逻辑单位用于覆盖首根和末根蜡烛的完整槽位。横向坐标裁剪到 `[0, timeScale.width()]`；区间完全位于视窗外、坐标不可用或首尾记录不存在时隐藏覆盖层。纵向高度只取第一个价格窗格，不延伸到成交量、持仓量和时间轴。

5分钟时间轴通过 `subscribeVisibleLogicalRangeChange()` 触发重算；已有 `ResizeObserver`、`layoutPanes()` 和副图开关完成布局后也安排重算。更新使用 `requestAnimationFrame` 合并同一帧内的连续事件，避免滚轮和拖动时频繁写入样式。

### 3. 只接受真实的60分钟指针悬浮作为高亮来源

60分钟 `subscribeCrosshairMove()` 在确认指针位于本图、事件对应有效K线且不是跨图程序化同步时，更新右图悬浮区间。现有十字光标同步逻辑可以继续工作，但不得借由合成事件反向创建悬浮状态。

以下事件清除悬浮区间：

- 指针离开60分钟图；
- 交叉光标事件没有对应60分钟K线；
- `childrenFor()` 没有返回5分钟记录；
- 加载或切换数据集；
- 图表进入无法计算有效坐标的状态。

右图自身的鼠标移动不创建新的区间高亮。悬浮更新不得调用 `highlight()`、`focus()` 或修改全局 `selected`。

### 4. 点击时复制左图可见逻辑跨度，而不是相同时间长度

在处理60分钟点击前读取左图：

```text
sourceSpan = visibleRange.to - visibleRange.from
```

右图目标中心使用首尾5分钟子记录逻辑索引的中点。目标跨度按以下规则确定：

```text
minimumSpan = childCount + 4
targetSpan = max(sourceSpan, minimumSpan)
targetSpan = min(targetSpan, totalFiveMinuteBars)
```

额外4个逻辑单位等价于子区间左右各保留约2根K线的上下文，避免首尾蜡烛贴边。以目标中心生成范围后，在数据集首末端整体平移范围；仅当5分钟总数据量小于目标跨度时显示全部数据。

这样左图可见30根60分钟K线时，右图通常可见约30根5分钟K线，蜡烛宽度接近；若左图只显示8根而子区间有12根，右图会扩大到至少16根，保证子区间完整。

目标逻辑范围计算提取为不依赖图表实例的纯函数，以便覆盖常规区间、短桶、超小源跨度和数据首末边界。若左图暂时无法返回有效范围，则沿用当前120根的回退跨度，避免点击失效。

备选方案是同步左图显示的实际时间长度。由于一根60分钟K线通常对应9至12根5分钟K线，该方案会让右图展示约十余倍数量的蜡烛，与“不要拉得这么远”的目标相反，因此不采用。

### 5. 保持现有联动入口的行为边界

`selectBar()` 只有在 `period === 60` 且存在5分钟子记录时，才把左图跨度传给右图的新范围定位方法。点击5分钟K线、日期跳转、异常跳转、标的切换和“回到最新”继续使用各自现有行为，避免本变更扩大到未提出的导航语义。

点击选择前后不需要清除悬浮状态；只要指针仍位于同一根60分钟K线上，高亮框可以与黄色选中标记同时存在。鼠标离开后仅清除高亮框，点击选中标记保留。

### 6. 分层验证坐标计算与真实交互

单元测试覆盖目标逻辑范围纯函数：

- 源跨度大于子区间时保持源跨度；
- 源跨度过小时扩大到子区间加边距；
- 9根盘末短桶；
- 靠近数据首端、末端时平移但不缩短；
- 总数据量小于目标跨度时显示全部。

Electron/Playwright冒烟测试使用真实60分钟蜡烛触发悬浮和点击，验证：

- 覆盖层显示、首尾区间标识和正宽度；
- 覆盖层不进入成交量或持仓量窗格；
- 鼠标离开及切换标的后清除；
- 右图缩放、拖动或窗口变化后覆盖层坐标更新；
- 点击前左图的逻辑跨度与点击后右图跨度符合规则；
- 既有12根、9根区间计数和点击选择状态不回归。

## Risks / Trade-offs

- [十字光标合成事件误触发悬浮] → 同时检查60分钟图的 `pointerInside`、事件来源和现有同步守卫，只让真实指针事件更新悬浮状态。
- [覆盖层阻挡图表操作] → 设置 `pointer-events: none`，覆盖层不参与命中测试。
- [滚轮或拖动期间样式更新过密] → 使用 `requestAnimationFrame` 合并坐标重算，并只在悬浮目标存在时执行。
- [价格窗格高度晚于容器变化更新] → 在图表布局完成后的动画帧读取 `panes()[0].getHeight()`，不缓存旧高度。
- [区间靠近视窗或数据边界时被裁切] → 屏幕坐标负责视窗裁剪，目标逻辑范围负责数据首末端平移，两类边界分别处理。
- [悬浮框与点击标记视觉混淆] → 悬浮使用低透明度冷色矩形，点击继续使用黄色方块，并保持独立生命周期。

## Migration Plan

本变更不涉及数据或配置迁移。实施后通过类型检查、单元测试和Electron冒烟测试验证，再生成应用构建。若需要回退，可移除悬浮覆盖层及其订阅，并恢复点击60分钟时调用原有固定120根的 `focus()`；数据文件和用户选择状态不受影响。
