## Context

现有领域逻辑已经能够从 `WeeklyEntry` 计算完整的 `EntryLifecycle`，并使用 1 分钟数据优先判断止盈、止损和休市出场；1 分钟、5 分钟和 60 分钟数据也已经随当前 `Dataset` 一起加载。渲染层已经在 60 分钟图表中维护历史入场集合，并且已有“入场规则”对话框可作为交互和视觉模式参考。

本变更只针对当前加载的数据集做内存中的历史复盘，不需要保存用户配置或新增行情请求。交易规则本身继续由现有生命周期分析负责，复盘模块只消费生命周期结果并做资金换算、排序和汇总。

## Goals / Non-Goals

**Goals:**

- 在现有工具栏增加可打开的“盈亏情况”复盘视图。
- 复用既有的入场、止盈、止损、休市出场和一分钟优先判定结果。
- 为每个有效入场生成独立交易记录，支持持仓重叠。
- 输出可测试的资金曲线、最终资金、收益率、出场分类和风险指标。
- 将未完成交易与未触发真实入场的候选生命周期明确区分。
- 复盘视图在数据重新加载后使用最新数据重新计算。

**Non-Goals:**

- 不修改入场、止盈、止损或休市出场规则。
- 不计算手续费、滑点、保证金占用、资金利息或税费。
- 不实现动态仓位、复利加仓、资金不足限制或持仓净额限制。
- 不将未完成交易按当前价格估值。
- 不新增导出文件、远程报表或持久化交易记录。

## Decisions

### 1. 新增纯领域复盘计算层

新增独立的复盘模块，输入历史 `WeeklyEntry[]`、5 分钟行情、1 分钟行情和价格最小变动单位，输出不可变的复盘结果对象。模块内部逐个调用现有生命周期分析，然后将包含真实入场和出场信号的生命周期转换为已完成交易，将包含真实入场但没有出场信号且到达数据末尾的生命周期转换为未完成交易。

选择独立领域模块而不是把计算散落在渲染代码中，是为了让资金公式、统计边界和异常场景能够通过纯函数测试，并避免“盈亏情况”视图复制交易规则。

### 2. 采用固定的显式资金参数

复盘参数固定为：

- `initialCapital = 1_000_000`
- `contractsPerTrade = 1`
- `contractMultiplier = 10`
- `fee = 0`
- `slippage = 0`

价格盈亏先按方向计算，再乘以合约乘数和手数。金额和汇总金额保留数值精度，渲染时使用中文本地化格式；价格仍遵循现有市场最小变动单位。

选择显式参数而不是从界面输入，是因为本次需求只要求复盘当前既定方案，避免第一版引入容易误改的交易配置入口。

### 3. 已实现资金曲线按出场事件排序

已完成交易按实际出场事件时间升序排序。存在一分钟判定时使用一分钟记录时间作为事件时间，五分钟收盘出场使用对应 K 线收盘时间；相同事件时间使用入场时间和稳定的原始顺序作为次级排序，确保结果可重复。

资金曲线只在交易完成时更新，初始资金作为第一条基线。最大回撤从每个资金曲线峰值到之后最低值计算。重叠交易不做净额合并，每笔交易的盈亏都按自己的出场事件加入曲线。

### 4. 把生命周期状态映射为三类出场统计

复盘层只接受现有生命周期给出的第一处实际出场：

- `take-profit` 计入止盈；
- `stop-loss` 计入止损；
- `session-close` 计入休市出场。

没有真实入场的生命周期直接忽略；已真实入场但没有出场信号且分析范围到达数据末尾的生命周期进入未完成列表。这样可以保持复盘与图表上的实际出场标记一致。

### 5. 复盘入口沿用现有渲染层模式

在工具栏中将“盈亏情况”放在“入场规则”旁边，沿用现有按钮和 `dialog` 的交互模式。按钮打开时，在当前渲染进程内使用已加载的 `dataset` 和 60 分钟图表保存的历史入场集合计算结果，不增加新的 IPC 或数据服务请求。

对话框按以下顺序展示：

1. 资金结果：初始资金、最终资金、总盈亏、收益率；
2. 交易统计：总交易数、胜率、止盈/止损/休市次数、持平数；
3. 盈亏质量：累计盈利、累计亏损、平均盈利、平均亏损、盈亏比、最大回撤；
4. 逐笔交易明细；
5. 未完成交易和数据质量提示。

采用当前数据重新计算而不是缓存结果，确保行情更新或重新加载后不会显示旧的复盘结论。没有已加载数据时按钮应保持可用但点击后显示加载提示，避免空白对话框。

### 6. 为测试提供稳定的结果边界

复盘结果类型应同时包含汇总结果、已完成交易数组、未完成交易数组和基础统计计数。交易记录保留生命周期引用所需的时间、方向、价格、出场类型及判定粒度，避免 UI 重新推导交易结果。领域测试覆盖多空方向、三种出场、重叠交易、未完成交易、无亏损盈亏比和最大回撤。

## Risks / Trade-offs

- [风险] 豆粕主连跨合约换月时可能存在价格连续性差异，直接使用已有连续行情会影响跨换月交易的价格盈亏。→ [缓解] 复盘沿用图表当前展示的主连数据，并在视图中展示数据范围；不在本变更中擅自复权或拼接价格。
- [风险] 同一 5 分钟 K 线内的价格先后顺序存在不确定性。→ [缓解] 复用现有一分钟优先、五分钟保守回退的生命周期结果，并在逐笔明细中显示判定粒度。
- [风险] 交易重叠会让理论资金曲线不同于单仓位实盘资金曲线。→ [缓解] 在复盘视图中明确每笔交易独立按 1 手统计，并展示交易总数；本变更不模拟保证金和资金占用。
- [风险] 数据末尾未完成交易若被估值会误导最终收益。→ [缓解] 单独展示未完成交易，禁止其进入已实现资金和收益率。
- [风险] 复盘明细数量较大时对话框可能变长。→ [缓解] 对话框内容区域使用滚动布局，先展示摘要，再展示逐笔明细和未完成列表。

## Migration Plan

1. 增加复盘领域类型、纯计算函数和单元测试。
2. 接入当前已加载数据和历史入场集合。
3. 增加“盈亏情况”按钮、复盘对话框、样式和渲染测试。
4. 运行类型检查、单元测试、打包和离屏 GUI 测试。
5. 不需要数据迁移；回滚时移除入口和复盘模块即可恢复原有行为。

## Open Questions

无。初始资金、仓位、合约乘数、手续费和滑点、重叠交易以及未完成交易的处理方式均已确认。
