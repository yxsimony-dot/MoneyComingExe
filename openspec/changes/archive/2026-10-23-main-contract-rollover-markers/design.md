## Context

当前应用使用 EDB 的豆粕主连 1 分钟数据聚合出 5 分钟和 60 分钟 K 线，快照只保存价格文件。主连在实际交易中会切换到新的具体合约，因此价格连续性本身不能作为换月证据；本变更需要把具体合约映射、换月时间、快照回退和图表展示接入同一条更新链路。

## Goals / Non-Goals

**Goals:**

- 使用主连和具体合约日线的持仓与价格字段做确定性换月识别。
- 在交易时间轴上定位新主力生效后的第一根 5 分钟 K 线，并映射到 60 分钟图。
- 让换月 CSV 与两份价格 CSV 一起进入版本化快照、哈希校验、回退和发布包。
- 兼容现有 schema 1 用户快照，并避免价格数据因 schema 升级回退。
- 让“更新行情”同时维护价格和换月信息，成功后立即刷新两个图表。

**Non-Goals:**

- 不根据价格跳变、成交量突变或持仓突变单独猜测换月。
- 不允许 renderer 或任意 IPC 参数指定外部 symbol、URL、header 或文件路径。
- 不改变现有 EDB 网络访问白名单和离线图表的整体行为。

## Decisions

### 1. 在主进程生成候选具体合约

主进程根据豆粕合约月份生成受控的 `DCE.mYYMM` 候选集合，并串行或低并发请求具体合约日线。renderer 只接收已经校验过的换月记录。这样可以维持现有网络策略，避免把任意 symbol 透传到 IPC 或远程请求中。

备选方案是只请求主连并根据价格启发式推断，但无法区分真实换月与行情跳动，因此不采用。

### 2. 使用六字段唯一匹配，忽略 open

主连日线和具体合约日线以 `high`、`low`、`close`、`volume`、`open_oi`、`close_oi` 做唯一匹配。主连 `open` 可能经过连续合约口径处理，与具体合约开盘价不完全相同，因此不把它作为匹配条件。缺失或多匹配都视为更新校验失败。

备选方案是按 `close_oi` 最大者选主力或使用交易量排序；这种方法在边界日可能产生不确定结果，因此不采用。

### 3. 用前一交易日收盘后的第一根 K 线作为换月时间

当交易日映射从前一日合约变为当日合约时，记录切换。随后在 5 分钟行情中查找严格晚于前一交易日 15:00:00 的第一根 K 线，因此可以覆盖当晚 21:00、周五夜盘或无夜盘时下一个交易日 09:00 等情况。60 分钟标记使用首个 `startMs >= rollover.timeMs` 的 K 线。

备选方案是把标记固定到换月交易日 09:00，但会错误覆盖夜盘生效的实际首根 K 线，因此不采用。

### 4. 快照 schema 升级到 2，并为旧快照提供回退

schema 2 的 metadata 增加 `files.rollovers`。schema 1 用户快照仍可验证和加载，换月数据使用内置 CSV；成功更新时从当前价格快照覆盖的首根 K 线开始重新计算并保存 schema 2。用户快照的价格数据优先级高于内置基线，schema 升级不能让其回退。

### 5. 以换月映射指纹参与“是否有变化”判断

更新协调器除了比较 5 分钟和 60 分钟行变化，还比较换月记录的稳定序列。只要任意一类数据变化，就进入原子保存；否则报告 up-to-date。

### 6. Renderer 为两个周期分别选择目标 K 线

换月记录在共享 Dataset 中传给两个 `MarketChart`。5 分钟图按精确首根时间匹配；60 分钟图选择第一个不早于换月时间的 K 线。换月 marker 使用独立 id、较高 size 和醒目颜色，合并到已有 markers 数组后按时间排序，并设置数据属性供 smoke test 和诊断使用。

## Risks / Trade-offs

- [候选合约日线请求数量增加] -> 只生成固定豆粕月份候选，复用同一受控 EDB client，并将请求限制在更新范围和有限未来窗口。
- [某个交易日源数据暂时缺失] -> 缺失或歧义时整次更新失败，不激活部分映射；用户可以稍后重试。
- [旧快照没有换月文件] -> 读取时使用内置 CSV 回退，成功更新后自动升级到 schema 2。
- [60 分钟标记与 5 分钟首根不完全同一时间] -> 明确使用首个 `startMs >= rollover.timeMs`，避免把标记放在换月前的 60 分钟 K 线上。
- [图表标记文本较长] -> 使用独立颜色、arrowDown 和 size 3，并通过 id 与 dataset 诊断属性验证其存在；不修改周一标记开关语义。

## Migration Plan

1. 将内置换月 CSV 随应用数据目录打包。
2. 读取旧 schema 1 用户快照时加载价格并附加内置换月记录。
3. 下一次更新成功后写入 schema 2，保留现有快照回退机制。
4. 若新逻辑发布后出现校验失败，旧 schema 1 快照仍可读取；回滚应用版本时旧版本会忽略新增换月文件。

## Open Questions

无。候选合约范围、字段匹配规则、换月首根时间和兼容策略均已确定。
