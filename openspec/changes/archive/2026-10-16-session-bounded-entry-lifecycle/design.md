## Context

动机见 `proposal.md`，可验收行为见 `specs/session-bounded-entry-lifecycle/spec.md`。

当前 `src/domain/weekly-entry.ts` 通过 `entryObservationWindow()` 从回调触发K线开始固定截取16根5分钟K线。红框、白色入场线、止盈止损和实际出场状态机都消费这同一个数组，因此计算、绘制和点击定位被绑定在固定窗口上。`src/renderer/main.ts` 也把同一数组同时传给 `highlightEntry()` 和 `focusBars()`；若只把数组扩展到整场，点击后会把过长范围纳入价格与时间缩放，重新造成K线被压扁。

现有行情模型已经用北京时间交易分钟索引区分日盘与夜盘，并支持每根5分钟K线独立选择完整1分钟证据或5分钟保守回退。设计需要复用这两项事实，同时将“完整生命周期分析范围”和“初始点击视口范围”拆开。

## Goals / Non-Goals

**Goals:**

- 用明确的交易时段策略构造从回调触发到实际出场或自然休市的完整生命周期。
- 让真正入场截止、持仓强制平仓和未入场自然结束成为领域层可测试结果。
- 复用现有红框、入场价、止盈止损及分钟事件状态机，不在渲染层重复交易判断。
- 让所有入场线段和标记消费同一个生命周期终点，同时保留紧凑点击定位。
- 对数据尚未到达休市边界的情况保持待完成状态，不制造未来K线或出场。

**Non-Goals:**

- 不修改60分钟入场信号、回调触发、红框上下沿或任何价格公式。
- 不新增1分钟可见图表、真实订单、成交滑点、手续费或盈亏统计。
- 不允许用户配置交易时段、入场截止时间或休市强制平仓时间。
- 不扩展到当前日盘15:00和夜盘23:00之外，也不跨交易日期追踪持仓。
- 不改变普通60分钟K线的黄色子K线联动和悬浮高亮行为。

## Decisions

### 1. 用交易分钟索引定义会话策略

领域层复用 `tradingMinuteAt()` 的北京时间日期、`session`、`index` 和 `total`，以固定策略表达边界：

```text
day:
  entry cutoff index = 210   # 14:45
  session end index  = 225   # 15:00
  forced close bar   = index 205..210  # 14:40-14:45

night:
  entry cutoff index = 105   # 22:45
  session end index  = 120   # 23:00
  forced close bar   = index 100..105  # 22:40-22:45
```

生命周期只接收与触发K线具有相同北京时间日期和 `session` 的后续记录。使用交易分钟索引而不是运行机器本地时区或字符串比较，可保持午间休市、北京时间和测试环境一致。

备选方案是只比较 `Bar.session` 并一直取到下一种 session。该方案可能在缺失数据时跨到下一交易日，因此不采用。

### 2. 领域层返回显式生命周期结果

将固定窗口替换为一个领域结果，概念结构如下：

```text
EntryLifecycle
  analysisBars          从触发到当前生命周期终点的实际5分钟K线
  focusBars             仅用于初始点击定位的紧凑触发附近范围
  entryCutoff           14:45或22:45
  sessionEnd            15:00或23:00
  forcedExitBar?        14:40-14:45或22:40-22:45
  reactionRange?
  quarterSignal?
  stopLossSignal?
  takeProfitSignal?
  exitAnalysis?
  endReason             take-profit | stop-loss | session-close |
                        no-entry-session-end | data-end
```

`analysisBars` 是计算和绘制的单一事实；`focusBars` 保留当前触发K线加后续最多15根的紧凑语义，但不再限制分析。`data-end` 表示行情尚未覆盖可判定终点，不能当作休市或实际出场。

备选方案是继续返回一个 `Bar[]` 并由渲染层推测是否入场、是否休市。该方案无法可靠区分无入场休市、持仓强制出场和数据截断，也会继续把视口与分析耦合，因此不采用。

### 3. 入场价计算与可入场时间分离

第一根方向反应和红框范围继续在所属交易时段的实际生命周期K线中按既有规则确定。白色入场指标线仍从反应K线下一根开始搜索触碰，但真正入场候选必须满足对应5分钟K线的交易分钟起始索引小于 `entry cutoff index`。

这样即使第一根方向反应在截止后才出现，界面仍可展示红框和计划指标线；但 `entryBar` 保持为空，止盈止损状态机不会启动。14:40开始的最后一根可入场K线仍然合格，若其中发生入场，则交由同一根K线内的分钟顺序或5分钟保守回退继续处理。

实现时为白色入场信号计算增加明确的截止约束，而不是先在全部K线上找触碰后再由渲染层删掉标记。这样止盈、止损和休市判断不会意外消费截止后的伪入场。

### 4. 实际出场状态机增加休市终止

现有 `waiting-entry -> active-default-target -> active-adjusted-target -> exited` 状态机保留止盈、止损和风险侧优先级，并增加会话终止路径：

```text
waiting-entry
  | eligible entry touch
  v
active-default-target
  | risk-side touch
  v
active-adjusted-target

active-* -- first TP/SL ----------------------> exited
active-* -- forced bar completed, no TP/SL --> session-close
waiting-entry -- session end ----------------> no-entry-session-end
any nonterminal state -- data exhausted -----> data-end
```

持仓分析最多扫描到强制出场K线并包含该根。该根仍逐个使用现有判定单元：完整分钟覆盖时按分钟顺序，不完整时按5分钟保守优先级。若扫描后已经产生止盈或止损，直接使用该结果；只有仍处于持仓状态时，才按该根5分钟收盘价产生 `session-close`。

`EntryExitType` 扩展为 `take-profit | stop-loss | session-close`。休市结果没有触发分钟，出场价为强制K线 `close`，`lineEndMs` 为该K线 `endMs`。为避免把休市收盘误称为保守回退，可将出场判定来源扩展为 `one-minute | five-minute-fallback | five-minute-close`，其中最后一种只用于休市出场。

备选方案是在渲染层看到时间后直接补一个“休市出场”标记。该方案会绕开实际出场状态机，无法正确处理强制K线内先止盈止损以及同根入场的顺序，因此不采用。

### 5. 先确定实际终点，再裁剪统一绘制范围

生命周期计算先取得同场完整候选K线，再按结果生成最终 `analysisBars`：

- 已止盈或止损：包含对应实际出场K线，之后全部裁掉。
- 已休市强制出场：包含强制出场K线，之后全部裁掉。
- 未入场且已有完整时段数据：包含到14:55-15:00或22:55-23:00最后一根。
- 数据尚未到达终点：包含到当前最后一根，结束原因为 `data-end`。

渲染选择状态只保存这一组最终K线和领域信号。触发方向标记、后续方向方块、绿色动态回调线、红框、白线、止损线、止盈线、风险侧标记和出场标记都从同一选择状态生成。计划线各自仍遵守既有起点，但终点统一使用 `analysisBars` 的末尾或实际出场的 `lineEndMs`。

“休市出场”使用独立文字和不与红色上涨K线混淆的既有出场色系。若同一强制K线已经是止盈或止损，只显示对应的唯一实际出场标记。

### 6. 点击定位只消费紧凑范围

`selectBar()` 在入场选择时把完整 `analysisBars` 传给 `highlightEntry()`，但把 `focusBars` 传给右图 `focusBars()` 和价格范围保障逻辑。`focusBars` 继续采用现有触发附近最多16根及左侧逻辑跨度同步，因此生命周期从数小时延伸到休市也不会扩大初始视口。

图表 series 可以在初始视口之外保存完整线段。用户平移后自然看到后续标记，不需要在选中时调用全生命周期 `fitContent` 或全范围价格适配。

备选方案是先聚焦完整生命周期，再异步缩回紧凑范围。该方案会造成可见闪烁，并违反自动化窗口和交互稳定性预期，因此不采用。

### 7. 诊断字段和测试以结束原因为核心

渲染诊断状态增加生命周期首末索引、结束原因、入场截止、会话终点、强制出场K线及休市出场价格。原有观察标记计数不再固定为15，而应等于最终生命周期中触发K线之后的实际记录数。

领域测试覆盖日夜盘、午间间隔、截止前后入场、强制K线内入场、分钟优先、5分钟回退、无入场休市和数据截断。Electron测试覆盖长生命周期线段、唯一出场标记、切换清理及紧凑视口。所有自动化Electron和EXE验证继续遵守 `AGENTS.md`：JavaScript测试通过 `tests/electron-test-launch.mjs` 的 `launchElectronTest()` 启动，直接EXE测试追加 `--test-window-offscreen` 并验证窗口矩形与全部显示器无面积交集。

## Risks / Trade-offs

- [同一选择的绘制点从16根增加到最多完整日盘225分钟] -> 5分钟层面最多约45根，现有 series 和 markers 足以承载；只重绘当前选择，不为全部历史信号预计算生命周期。
- [数据缺口可能让当前数组看似到达最后一根但并不完整] -> 只有实际存在且时间边界正确的强制K线或时段末根才能产生终止结果，否则保持 `data-end`。
- [截止后仍绘制红框和白线可能被误认为还能入场] -> 不显示真正入场标记，也不启动止盈止损；规则说明明确截止后的线只用于观察。
- [强制出场K线内分钟不完整时无法知道精确先后] -> 复用已确认的5分钟保守优先级，再把收盘强制出场作为最后兜底。
- [扩展出场类型影响现有穷尽分支] -> 通过TypeScript穷尽检查、领域测试和渲染标记测试覆盖所有三种实际出场。
- [完整生命周期与视口拆分后可能误传数组] -> 在选择状态中使用不同字段名，并用超长生命周期测试断言初始逻辑跨度不随终点增长。

## Migration Plan

1. 增加交易时段生命周期构造与边界测试，保留旧固定窗口函数作为临时的紧凑 `focusBars` 来源。
2. 为白色入场信号增加入场截止约束，并把实际出场分析扩展到强制K线和 `session-close`。
3. 将渲染选择状态切换到完整生命周期结果，统一线段、方向标记和实际出场终点。
4. 把点击定位改为只使用紧凑 `focusBars`，补充长生命周期下的时间与价格缩放回归测试。
5. 同步用户规则文档、应用内规则文本、领域测试和离屏Electron/EXE测试。
6. 回退时可恢复固定16根分析入口并移除 `session-close` 分支；行情快照、CSV和用户配置均无需迁移。
