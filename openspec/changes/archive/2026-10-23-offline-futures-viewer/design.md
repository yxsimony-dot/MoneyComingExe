## Context

动机与产品范围见proposal.md。当前工作区只有已下载的数据和调查材料，没有既有应用、Git仓库或测试系统。数据目录为futures_investigation_20261009，四份EDB聚合CSV合计30,787根K线；其中主连5m/60m为16,530/1,438根，2701为11,793/1,026根。

CSV带UTF-8 BOM，时间字段bar_start/bar_end无时区后缀但语义固定为北京时间；包含OHLC、volume、open_oi、close_oi和完整性信息。60分钟按累计交易分钟切分，包含午休和45分钟收盘桶。cross_source_audit.json已记录具体合约的跨源差异，不能把complete=True解释成数据真实可靠。

## Goals / Non-Goals

**Goals:**
- 将文件读取、行情数据模型、区间匹配、图表展示和Windows打包分开，使离线交付与时间逻辑可独立验证。
- 用同一份已有聚合数据驱动K线、量柱和持仓，确保显示值可回查原CSV。
- 交付可整体移动的目录，目标Windows 10/11 x64；界面尺寸最低1100×720，默认1440×900或适配工作区。

**Non-Goals:**
- 不在运行时重新聚合分钟数据，不替换数据商算法，不为缺失价格插值。
- 不建立后端服务或数据库，不将原始采集脚本接入运行时。
- 不实现指标引擎。均线、MACD等可在基础看盘验收后另立变更。

## Decisions

### 1. 桌面与图表技术

采用Electron + TypeScript + Vite（原生DOM界面）+ Lightweight Charts。构建工具用electron-builder，输出Windows目录包再ZIP。

理由：成熟图表支持蜡烛、柱图、折线、缩放和十字光标；Electron随包带运行环境，有利于同一份本地界面在用户电脑直接启动。当前交互状态有限，无需额外引入前端UI框架。

备选：Python+Qt可以直接读CSV，但高质量金融图表交互仍需额外实现或嵌入网页；Tauri体积更小，但增加Rust构建与WebView运行时交付考虑。优先选容易验收的Electron，接受包体较大。

依赖在实施时选择相互兼容的稳定版本并提交锁文件，不使用CDN或远程字体。保留Lightweight Charts的许可证、NOTICE与所需TradingView署名；关于窗口提供来源信息，外链仅用户主动点击时打开外部浏览器。

### 2. 应用边界与目录

建议代码目录：src/main（窗口、本地数据读取），src/preload（有限IPC桥），src/shared（数据类型和校验），src/renderer（页面与图表），src/domain（时间、定位和联动纯逻辑），tests（关键行为测试），scripts（打包准备）。

数据流：本地CSV → 主进程读取/解析/校验 → 类型化数据包 → 渲染进程缓存 → 图表与数值面板。主进程只接受白名单标的/周期，不接受任意路径；渲染进程关闭Node集成、启用上下文隔离和沙箱。正式版本仅加载打包资源，不启动HTTP服务，不进行行情网络请求。

开发时由显式项目路径读取已有调查目录；打包时复制四份EDB CSV、summary.json和审计材料到EXE同级data目录。正式运行以EXE所在目录定位data，不能依赖当前工作目录或开发机绝对路径。读源文件，不写源文件。可选审计文件损坏只影响提示，核心CSV损坏阻止对应标的展示并提供重试。

### 3. 数据契约与缓存

Bar包含startMs/endMs、原始显示字符串、OHLC、volume、openOi/closeOi、session、observedMinutes/expectedMinutes、complete。显式按UTC+08:00解析日期并校验日历有效性，禁止依赖Windows时区或Date对无后缀文本的默认解析。

启动加载主连，后台或首次切换加载2701；每个标的两周期一起校验并缓存。加载失败保留可用标的，不显示前一个标的数据冒充新标的。验证列齐全、非空、数值有限、量与持仓非负、start<end、价格范围、严格时间顺序和重复。格式错误返回文件名、行号和原因，不静默排序/丢行。结构合理但可疑低价保留。

图表时间键使用bar_end对应的UTC秒，显示格式固定Asia/Shanghai。横轴按数据记录连续排列，休市不填空K线；若前端默认格式使用UTC，覆盖轴标签、光标时间、标题及日期定位所有格式化入口。

### 4. 布局与交互

顶部：标题、标的下拉框、双图/5分钟/60分钟、日期输入、定位、回到最新。底部：来源、起止范围、K线数量、异常入口。默认左60m右5m，两侧各有价格区、成交量区、持仓区，同周期副图共享时间轴和光标。

初始展示各周期最新120根（不足则全部）；用户可以浏览全部已载入数据。切换单图只改变布局，不销毁数据缓存。切换标的保留当前关注时间并就近定位；首次启动默认主连。光标显示该根起止时间、OHLC、成交量、收盘持仓与开收盘持仓差，不能把相邻记录混入。

日期定位规则：用户输入北京时间自然日，取该日第一根；若无记录，取之后第一根，超出末尾则取末根，早于首条则取首根，并提示实际定位日期。切换标的则保留精确关注时间（选中K线的bar_start，无选中时取视窗中心记录的bar_start），优先查找start<=时间<end的记录，无包含记录时取之后第一根并夹取首末边界，不重置到日首。日期为空或不合法时显示输入错误，不跳转。夜盘显示实际自然日，不计算未经验证的交易日归属。

### 5. 双周期联动

点击60m：定位并高亮所有满足parent.start<=child.start且child.end<=parent.end的5m记录；保留周围上下文，非简单放大到极少数K线。点击5m：用同一包含规则寻找60m父桶，定位并高亮。默认同步光标选中提示，但只在点击/定位操作时移动另一图的视窗，避免拖动和光标事件相互触发导致抖动。

同一标的60m例：09:00—10:00含12根；10:00—11:15跳过10:15—10:30，含12根；11:15—14:15跳过午休，含12根；14:15—15:00含9根。21:00—22:00与22:00—23:00各12根。比较区间，不能用序号乘12或自然小时取整。关键边界：结束于10:00的5m属于09:00—10:00，开始于10:00的5m属于下一桶。

60m有记录但组成5m缺失或对不上时，仅显示已找到的数据并提示不能完整联动。通过交互来源标识或单向更新状态阻止递归事件。普通历史浏览允许显示完整60m，不提供回放时间游标或信号计算。

### 6. 数据质量提示

导入审计JSON中的已知可疑分钟，以标的+时间映射到包含它的5m/60m记录。至少标记2701的2026-02-05 09:20—09:25和09:00—10:00，保留low=2720。点击标记显示原值、来源差异及“待核实”；新浪2901仅是09:00—10:00的60m低价对照，不替换EDB。5m提示若引用2901必须明确写“所属60分钟的新浪对照低价”，不能当作同一根5m对照值。

图表顶部轻量显示“历史数据，截至2026-10-09”。异常详情说明完整性标记仅检查组成分钟，不保证价格正确。可选审计材料缺失时显示“异常提示资料未加载”，行情仍能浏览。主连标明源价格、未自行复权；不拼接新浪与EDB。

### 7. 验证与性能

单元测试聚焦北京时间解析、CSV错误、跨休市区间匹配、收盘短桶、日期夹取与已知异常映射。数据集验收对照四份CSV行数、首末时间、随机数值和关键边界，不为纯样式编写镜像测试。

集成验收覆盖两标的、三种布局、图表缩放/拖动、十字光标、日期跳转、点击联动、窗口缩放、缺文件恢复。至少保存默认双图与异常点的截图审查。自动化优先使用浏览器展示同一渲染代码的测试入口和Electron启动测试，最终必须真实运行打包EXE，不能只以网页截图替代。

目标机器记录性能环境与至少三次运行数据：从进程启动到默认两图可交互不超过5秒，已缓存标的切换不超过1秒；连续拖动期间不出现超过200ms的主线程长任务。若未达到，先定位解析、重复setData或事件递归，不为了性能截掉历史。所有数值是验收目标，不是已经测得的承诺。

### 8. 分发

输出MoneyComing/目录，含MoneyComing.exe、Electron必需运行资源、data/和使用说明.md，完整目录压缩为MoneyComing-win-x64.zip。不能只复制EXE忽略DLL/resources。用户可离线解压启动，无需Python、Node、管理员安装或开发服务器。

采用目录包以便数据独立更新，暂不用自解压单EXE，避免解压临时目录导致数据定位不清。首次交付为本地未签名构建，验证其启动状况并如实记录；不在提案阶段承诺签名证书。

## Risks / Trade-offs

- [源数据有跨源价量差异] → 保留原值、来源与异常标记，不把浏览工具当作数据修复结论。
- [原生图表默认UTC显示] → 集中北京时间格式化，并用不同系统时区测试同一光标日期。
- [跨周期联动边界错误] → 采用真实包含区间，对午休、边界结束、45分钟桶编写明确案例。
- [Electron包体较大] → 只打包必需应用资源和四份CSV；不携带依赖源码、原始1m大文件或开发工具。
- [便携目录被单独移动EXE] → 中文说明要求移动整个目录，缺data时显示可理解的路径与重试操作。
- [目标平台或UI自动化不可用] → 保留产物并报告未验证环节，不能声称已运行成功；正常实施目标仍为真实Windows启动验收。

## Migration Plan

这是新应用，没有既有用户配置迁移。构建时只复制现有数据，交付到独立dist目录并校验源文件未变化。升级以新目录并行交付；回退为启动旧目录，不改原始数据。此轮文档完成不表示应用已实现。
