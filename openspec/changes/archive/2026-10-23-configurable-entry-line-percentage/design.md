## Context

动机见 `proposal.md`，可验收行为见 `specs/entry-line-percentage-settings/spec.md` 和 `specs/session-bounded-entry-lifecycle/spec.md`。

领域层目前已有共享的 `EntryStrategySettings`，但只包含方向反应实体tick参数。白色入场价格计算仍固定使用 `ceil(rangeTicks / 4)`，该价格继续驱动真正入场、止盈、止损、实际出场、第二轮机会以及全盘盈亏复盘。渲染层已经有版本化本地设置键和统一刷新流程，因此新增参数应进入同一设置对象，不能由图表单独读取。

5分钟图为首轮和第二轮分别维护白色入场线序列，当前都关闭最后值显示且标题为空。自动化Electron和EXE测试必须继续遵守首次显示前离屏定位与窗口矩形无显示器交集的项目规则。

## Goals / Non-Goals

**Goals:**

- 用一个经过验证的整数百分比统一驱动首轮、第二轮、图表和盈亏复盘。
- 保持25%时与现有四分之一入场价格完全一致，包括非整除时向上补齐一个tick。
- 在同一策略面板中提供紧凑、可持久化且实时生效的百分比控件。
- 升级已有本地设置时保留用户当前的方向反应tick值。
- 让每一条实际存在的白色入场线都在右侧价格轴显示“入场”。

**Non-Goals:**

- 不修改60分钟信号、回调触发、方向反应红框、止盈公式、止损公式、休市规则或第二轮触发条件。
- 不允许小数百分比、百分比预设、参数历史、恢复默认按钮或多设备同步。
- 不修改十倍杠杆、全量资金递推或手续费口径。
- 不让一分钟K线显示在界面内。

## Decisions

### 1. 扩展现有策略设置对象

领域设置扩展为：

```ts
interface EntryStrategySettings {
  reactionBodyTicks: number;
  entryRangePercent: number;
}
```

新增最小值0、最大值100和默认值25，领域校验同时验证两个字段为有限整数且在各自范围内。生命周期、盈亏复盘和渲染层只传递完整设置对象，避免图表使用新百分比而复盘仍使用25%的分歧。

备选方案是给白线函数单独增加一个可选数字，但首轮、第二轮和复盘存在多条调用链，容易漏传，也会绕开现有持久化与统一刷新，因此不采用。

### 2. 百分比距离先在tick网格中计算并统一向上取整

计算步骤为：

```text
rangeTicks = round((high - low) / tick)
entryDistanceTicks = ceil(rangeTicks * entryRangePercent / 100)
distance = entryDistanceTicks * tick

longPrice = low + distance
shortPrice = high - distance
```

百分比表示从风险侧边界向盈利方向移动的距离：多头风险侧为红框最低点，空头风险侧为红框最高点。两个方向使用同一个非负tick距离，从而形成严格镜像。0%得到风险侧边界，100%得到另一侧边界，25%与现有 `ceil(rangeTicks / 4)` 等价。

先计算整数范围tick数，可避免直接对价格小数取整造成非1 tick标的不合法，也能保持“精确整除不多加tick、非整除向上一个tick”的现有规则。

### 3. 使用同一持久化键进行向后兼容的字段补全

继续使用现有策略设置存储键，加载时逐字段规范化：

1. 有效的 `reactionBodyTicks` 保留，否则使用其默认值。
2. 有效的 `entryRangePercent` 保留；字段缺失或无效时使用25。
3. 将规范化后的完整对象写回存储。

这样现有用户升级时不会丢失已经调好的方向反应门槛。相比直接更换存储键，该方案不需要额外读取和迁移两份键；相比整对象校验失败后全部恢复默认，它能隔离单个字段损坏。

### 4. 百分比控件复用现有参数面板交互

在方向反应tick控件旁增加“入场线”参数组，包含减号按钮、整数输入框、加号按钮和百分号单位。按钮在0和100边界禁用，输入框的临时空白、小数、越界或非数字状态不提交设置；失焦或按回车时恢复最近一次有效值。

面板继续依附“周一8根标记”的显示开关。隐藏面板只影响可见性，不改变两个策略参数。窄窗口允许参数组与摘要换行，并保持按钮和输入框稳定尺寸。

### 5. 有效百分比变化复用统一策略刷新流程

设置更新流程为：

1. 保存完整且已验证的设置对象。
2. 更新两个参数控件和诊断状态。
3. 若当前选中60分钟入场事件，保持选择与用户当前缩放，重新计算完整5分钟生命周期并替换所有策略线段和标记。
4. 使用同一设置对象执行一次全量盈亏复盘，更新面板摘要。
5. 若“盈亏情况”已打开，复用同一复盘结果刷新完整内容。

不为百分比另建一套刷新逻辑，避免与方向反应tick参数出现先后顺序或结果缓存不一致。图表重算必须替换旧生命周期状态，不能只移动白线，因为入场变化会连锁改变后续止盈、止损、出场和第二轮资格。

### 6. 白线序列开启最后值标签但继续排除自动缩放

首轮和第二轮白色序列都使用：

```text
lastValueVisible: true
title: "入场"
autoscaleInfoProvider: () => null
```

白线仍为白色实线，价格格式继续使用标的tick。“入场”与价格由图表价格轴在每条非空序列的最后数据点处显示；序列清空时标签随之消失。继续排除自动缩放，防止参数调到0%或100%时扩大价格范围并压扁K线。

### 7. 规则文字从固定四分之一改为参数化公式

应用内规则和外部规则文档同步使用“当前入场线百分比P”描述，并保留3020至3031、tick为1、P为25时多头3023和空头3028的例子。规则同时解释：

- P为0和100时对应的边界；
- 首轮与第二轮共享P；
- 向上取整的是百分比距离的tick数；
- 白线首次触碰、止盈止损与出场继续使用重算后的实际入场价格。

## Risks / Trade-offs

- [每次调节百分比都触发全量复盘，可能造成短暂卡顿] -> 只提交有效整数变化，复用一次复盘结果，并保持统一刷新入口可在需要时合并同一事件循环内的重复输入。
- [旧本地设置缺少新字段导致方向反应值被重置] -> 按字段规范化并增加旧对象升级测试。
- [0%或100%使入场线与红框边界或其他线重合] -> 保留“入场”价格轴标签和独立序列语义，不人为偏移价格。
- [两轮入场价相同导致价格轴标签视觉重合] -> 由图表库按同价序列处理，不改变交易价格；GUI测试验证至少存在可辨认的“入场”标签且没有旧价残留。
- [内部仍有“四分之一”命名造成误解] -> 实施时更新面向策略含义的字段、诊断和注释；若为降低一次性改动保留兼容标识，MUST 不再把它暴露为用户规则或百分比计算来源。
- [白线最后值标签意外参与自动缩放] -> 保留空的自动缩放提供器，并覆盖极端百分比的图表回归测试。

## Migration Plan

1. 扩展策略设置类型、默认值、校验和旧存储对象字段补全。
2. 将百分比传入白线计算及首轮、第二轮和盈亏复盘，补齐领域测试。
3. 增加参数控件并接入统一刷新流程和实时摘要。
4. 为两条白线开启“入场”价格轴标签，验证不影响自动缩放。
5. 更新应用内及外部入场规则，运行规则一致性测试。
6. 运行类型检查、领域测试、构建和按项目离屏规范执行的Electron/EXE验收。

回滚时可隐藏百分比控件并恢复25%的固定计算；持久化对象中的额外字段可被旧逻辑忽略，不需要迁移行情或复盘数据。
