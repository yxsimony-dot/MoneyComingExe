## Context

动机见 `proposal.md`，可验收行为见 `specs/five-minute-quarter-entry-line/spec.md`。

现有领域层通过 `entryObservationWindow()` 提供触发K线和后续15根5分钟K线，并通过 `entryReactionRange()` 返回方向、首次反应K线、前置极值K线、最高价和最低价。渲染层把该结果保存在5分钟 `entry` 选择状态中，使用独立DOM覆盖层绘制红框，同时通过图表折线序列绘制动态回调线。

当前唯一行情标的的主K线价格格式使用 `minMove: 1`，但领域计算尚未显式保存tick概念。新规则必须精确区分“能够被4整除”和“不能整除时向上补齐一个完整tick”，并避免浮点误差导致整除区间被错误增加tick。

## Goals / Non-Goals

**Goals:**

- 用纯函数从首次反应范围和tick计算多空镜像的入场指标价格。
- 用纯函数从首次反应K线之后搜索第一根触线K线，并严格限制在原观察窗口内。
- 让白线和真正入场标记跟随现有5分钟入场选择状态统一创建、重绘和清除。
- 让规则文件、内置回退文字、领域测试和Electron验收使用同一计算口径。

**Non-Goals:**

- 不修改 `analyzeWeeklyEntries()`、60分钟突破回调算法或现有60分钟标记。
- 不改变观察窗口的“触发根 + 后续15根”、动态回调线或首次反应红框边界。
- 不从首次反应K线后重新开启新的15根窗口。
- 不增加白线比例、颜色、tick或观察根数的用户配置。
- 不实现自动下单、仓位、止损、止盈或离场规则。

## Decisions

### 1. 以整数tick数量计算四分之一距离

领域层新增结构化结果和纯函数，输入首次反应范围、观察窗口与正数tick。计算步骤为：

```text
rangeTicks = round((high - low) / tick)
quarterTicks = ceil(rangeTicks / 4)
distance = quarterTicks * tick

longPrice = low + distance
shortPrice = high - distance
```

行情价格本身应落在tick网格上，因此先换算并四舍五入为整数tick数量，再执行 `ceil(rangeTicks / 4)`。这能保证12个tick精确得到3个tick，11个tick得到3个tick，不依赖二进制浮点小数是否恰好表示。

当前数据集使用共享常量 `tick = 1`，该常量同时供领域计算和5分钟白线价格格式使用。若未来加入不同最小变动单位的标的，应把tick加入行情元数据；本次不从K线小数位动态猜测tick，因为历史数据不一定包含每个合法价格步长。

纯函数返回类似结构：

```text
EntryQuarterSignal:
  direction
  price
  tick
  quarterTicks
  lineStartBar
  reactionBar
  entryBar?
```

其中 `lineStartBar` 沿用红框的 `extremeBar`，`entryBar` 只在找到第一次触线时存在。

备选方案是直接计算 `(high - low) / 4` 后对最终价格调用 `Math.ceil()` 或 `Math.floor()`。该方案把价格方向与取整方向混在一起，容易让空头产生不对称结果，也无法支持非1的tick，因此不采用。

### 2. 触线搜索复用原观察窗口索引

计算函数通过 `reactionBar.startMs` 在现有观察窗口中定位首次反应索引，并只扫描 `reactionIndex + 1` 到数组末尾。每根候选K线统一使用：

```text
bar.low <= entryPrice && entryPrice <= bar.high
```

第一次满足后立即返回该K线，不继续生成其他入场结果。反应K线位于末尾、索引不存在或剩余K线均不触碰时，保留白线结果但 `entryBar` 为空。函数不读取完整5分钟数组，因此无法越过原窗口边界，也不会隐式补足新的15根。

备选方案是在渲染层遍历后续K线。该方案会把影线触碰和首次命中的交易规则混入绘图代码，难以独立验证多空一致性，因此不采用。

### 3. 白线使用独立折线序列并覆盖原窗口剩余范围

5分钟图新增只用于入场指标的折线序列，使用白色实线、整数价格格式、隐藏最后值标签和十字光标圆点。数据点从 `lineStartBar` 开始，按相同价格覆盖到观察窗口最后一根；交易休市间隔继续沿用真实K线时间，不补造记录。

折线序列应关闭价格自动缩放影响，或在价格轴自动范围计算中排除该序列，保证新增白线不会再次造成K线被压扁。白线在首次真正入场后仍显示到原观察窗口末尾，便于用户检查后续价格；只有真正入场标记停止在第一次触碰。

备选方案是使用DOM绘制白线。DOM线需要同时处理横向时间坐标和纵向价格坐标，并重复红框的大量重绘逻辑；图表折线序列更适合恒定价格且能自然跟随时间轴，因此采用折线。

### 4. 真正入场标记与观察窗口标记并存

5分钟 `entry` 选择状态增加可选的四分之一信号结果。现有触发根方向箭头、后续弱方块、动态回调线和红框继续保留；若 `entryBar` 存在，额外在该K线上显示高对比度白色方向箭头并标注“入场”：多头位于K线下方并向上，空头位于K线上方并向下。

真正入场标记使用稳定ID，包含方向、触发时间和入场K线时间。诊断属性保存白线价格、tick数量、搜索起始索引、真正入场索引和触碰数量，供自动化测试验证第一根命中及清理生命周期。

备选方案是把原有弱方块直接改色。该方案会丢失观察窗口完整序列与真正入场之间的视觉区分，因此保留原标记并叠加独立入场箭头。

### 5. 白线和入场标记绑定现有选择生命周期

`highlightEntry()` 在首次反应范围存在时计算四分之一信号，并写入同一个 `entry` 选择状态。普通 `linked` 选择、无首次反应范围、数据集切换、回到最新和清除选择均清空白线序列、入场标记及诊断属性。

红框继续使用现有DOM重绘调度；白线由图表序列自动跟随时间轴与价格轴。新增状态不得写回 `WeeklyEntry`，因为真正入场是基于触发之后最多15根数据得到的5分钟观察结果，不能反向改变60分钟因果分析和既有标记。

### 6. 规则说明替换旧的“仅观察”结论

外部 `futures_investigation_20261009/entry-rules.md` 和内置 `src/shared/entry-rules.ts` 同步增加白线与真正入场规则。现有首次反应范围的定义继续保留，但原第20条中“不依据该范围新增、删除或移动自动入场信号”的结论需要替换为三阶段语义：

```text
回调触发 -> 首次方向反应范围 -> 四分之一白线首次触碰即真正入场
```

文档同时给出3020至3031、tick为1时多头3023和空头3028的例子，避免“对价格向上取整”与“对四分之一距离向上取整”再次混淆。

## Risks / Trade-offs

- [图表线序列可能参与价格自动缩放并压扁K线] -> 明确关闭该序列的自动缩放贡献，并增加价格范围回归测试。
- [整数tick换算遇到不在tick网格上的脏数据] -> 使用最接近整数的range tick数并在开发诊断中暴露计算值，原始K线数据保持不变。
- [同一K线同时显示弱观察方块和真正入场箭头] -> 使用不同尺寸、颜色、文字和上下位置，自动化及视觉验收确认不重叠。
- [白线从红框左边界开始，但真正入场搜索更晚开始] -> 规则和诊断明确区分“指标线可视范围”与“有效搜索起点”，首次反应K线绝不参与触线判断。
- [数据末尾或反应过晚导致没有可搜索K线] -> 保留白线以展示价格依据，但不生成虚假入场标记。
- [未来标的tick不为1] -> 本次集中定义共享tick常量，未来扩展时迁移为数据集元数据而不改变四分之一算法。

## Migration Plan

本变更不迁移行情数据或用户配置。实施顺序为先增加共享tick与领域纯函数及测试，再扩展5分钟选择状态、白线序列和入场标记，随后更新规则说明和Electron测试。

完成后运行单元测试、类型检查、构建、应用冒烟测试和Windows目录包构建，并在多头、空头、整除、非整除、影线首次触碰、重复触碰、无触碰和图表缩放场景下进行视觉验收。

回退时移除四分之一信号计算、白线序列和真正入场标记，并恢复旧规则文字；现有观察窗口、动态回调线、首次反应红框、60分钟入场事件和行情数据均不受影响。
