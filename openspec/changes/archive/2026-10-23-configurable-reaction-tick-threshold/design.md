## Context

见 `proposal.md`。当前方向反应范围函数在领域层把最小实体写死为 `tick × 2`，首轮和第二轮生命周期共享该函数。5分钟图表选中流程和盈亏复盘分别调用完整生命周期计算，因此若参数只接入其中一处，会造成图表与复盘结果不一致。

“周一8根标记”目前只有显示状态，没有设置面板。应用尚无同类策略配置；该参数只属于本机单用户策略，不需要远程同步。自动化Electron和EXE测试必须沿用项目规定的首次显示前离屏启动方式。

## Goals / Non-Goals

**Goals:**

- 建立单一、类型明确的方向反应tick参数，并贯穿首轮、第二轮、图表和复盘。
- 让参数调整、摘要更新和已打开的完整盈亏窗口形成一次一致的状态更新。
- 在不丢失当前60分钟事件选择的前提下刷新5分钟生命周期。
- 让设置跨软件重启和后续打包版本保持可用。

**Non-Goals:**

- 不修改60分钟周一范围、突破、回调触发或多空候选的生成规则。
- 不开放白线、止盈、止损、杠杆、手续费等其他策略参数。
- 不提供预设方案、参数历史、恢复默认值或多设备同步。
- 不改变现有盈亏资金递推和十倍杠杆口径。

## Decisions

### 1. 使用独立策略设置对象，不复用价格tick参数

新增领域层设置类型，至少包含：

```ts
interface EntryStrategySettings {
  reactionBodyTicks: number;
}
```

`tick` 继续只表示标的最小价格变动单位，`reactionBodyTicks` 表示实体需要跨越多少个tick。领域入口接收经过校验的设置，并把它传给每一轮共用的方向反应范围计算。这样可避免把“价格单位”和“数量参数”混为一谈，也为以后增加其他策略参数保留清晰边界。

备选方案是直接给多个函数增加一个数字参数，但容易在图表、复盘或第二轮调用中漏传，并且数字含义不直观，因此不采用。

### 2. 只在边界层规范化，领域层仍拒绝非法设置

界面将输入规范化为1至20的整数，步长固定为1。领域计算仍验证数值为有限整数且位于范围内，防止测试、未来调用方或损坏持久化数据绕过界面约束。判断使用 `>=`，不额外增加浮点容差；价格来自tick网格，现有测试需覆盖非单位tick。

输入框处于暂时空白、非数字或小数状态时，不提交新设置，也不触发重算；失焦或确认时恢复最近一次有效值。

### 3. 使用Electron渲染进程持久存储保存一个版本化键

使用稳定键保存最后一次有效的 `reactionBodyTicks`。启动时先读取、解析和校验，再进行首次生命周期或复盘计算；无值或值损坏时写回默认值1。该设置不跟随“周一8根标记”的开关清除。

相比增加主进程文件配置和IPC，该参数不含敏感信息、只由单一渲染进程使用，持久存储可减少跨层协议和迁移负担。版本化键允许未来改变结构时显式迁移。

### 4. 参数面板依附周一标记开关，但计算设置独立存在

工具栏为“周一8根标记”增加相邻设置区域。开启按钮时显示面板，关闭时隐藏；隐藏只影响可见性，不恢复或停用参数。面板包含减号、数值输入、加号，以及最终资金、总收益率和已完成交易数三个紧凑摘要，不另设说明性大卡片。

按钮在1和20边界分别禁用对应方向，输入框使用整数语义和可访问标签。布局在窄窗口下允许换行，避免工具栏和摘要互相覆盖。

### 5. 有效参数变化通过一个统一刷新流程传播

设置状态更新后按以下顺序处理：

1. 保存新的有效参数。
2. 若当前选中了60分钟入场事件，以同一事件和新参数重算5分钟生命周期，并替换全部相关线段、标记与诊断状态。
3. 使用同一参数执行全量盈亏复盘，更新面板摘要。
4. 若“盈亏情况”窗口已打开，用同一结果刷新完整内容。

统一刷新入口避免图表和两个复盘视图各自读取参数。当前图表选择和用户缩放尽量保持；刷新只替换策略结果，不主动重新定位到紧凑初始视口。无当前选择时只更新摘要和完整复盘状态。

### 6. 复盘函数显式接收设置，不读取界面或全局状态

盈亏复盘继续作为纯领域计算：调用者传入周一候选、5分钟数据、1分钟数据和策略设置。复盘内部创建每个生命周期时继续透传同一设置。参数面板和完整弹窗复用一次计算结果，避免同一设置变化触发两份可能不一致的算法。

若数据量导致数字输入连续变化时出现明显阻塞，可在渲染层合并同一事件循环内的重复刷新；每个最终有效值仍必须产生可见结果。加减按钮每次点击立即刷新。

### 7. 原有入场规则中的固定门槛原地替换

外部规则文件和内置确认版中，首轮多头、首轮空头、第二轮方向反应及相关示例的“至少2个tick”统一替换为“至少当前设置的N个tick”。规则明确说明：

- 实体正好等于N tick时合格；
- 小于N tick的同方向K线不结束搜索；
- 被跳过K线仍参与包含区间极值统计；
- 首轮和第二轮使用同一当前值；
- 首次无历史设置时N为1，之后使用上次保存值。

## Risks / Trade-offs

- [全量复盘在每次输入时可能阻塞界面] → 只对有效整数提交变化，复用一次复盘结果，并允许合并同一事件循环内的重复输入刷新。
- [图表与复盘漏传参数产生分歧] → 所有生命周期和复盘公共入口显式要求设置对象，并增加同一数据在两个消费者中的一致性测试。
- [旧持久化值损坏或未来格式变化] → 使用版本化键和严格范围校验，无效时回落并写回1。
- [参数变化后旧图形残留] → 重算前替换整个生命周期可视状态，并在GUI测试中从高门槛切换到低门槛及反向切换验证清理。
- [打开面板后工具栏在小窗口溢出] → 使用稳定控件尺寸、允许工具栏区域换行，并覆盖桌面窄宽度离屏截图测试。

## Migration Plan

1. 引入设置类型、默认值和校验，先让固定行为通过显式默认设置运行。
2. 将设置透传到生命周期、第二轮和盈亏复盘，补齐领域与复盘测试。
3. 接入持久化和参数面板，再实现统一刷新及摘要。
4. 更新外部与内置入场规则，运行规则内容测试。
5. 运行构建、领域测试和按项目离屏规范启动的Electron/EXE测试。

回滚时可移除面板与持久化读取，并把领域调用恢复为默认1 tick设置；不涉及行情数据或用户交易数据迁移。
