## Context

参见 `proposal.md` 的变更动机和本 change 下的两个 delta spec。

当前 `src/domain/weekly-entry.ts` 的 `EntryLifecycle` 只包含一组 `reactionRange`、`quarterSignal`、止损、止盈和出场结果，并在第一笔实际出场后立即截断 `analysisBars`。`src/renderer/main.ts` 的选择状态、红框覆盖层和计划线同样只支持一组结果；`src/domain/profit-loss-review.ts` 则对每个60分钟入场候选只读取一笔生命周期交易。

本变更跨越领域计算、图表渲染、盈亏复盘、规则文档和自动化测试。现有一分钟优先判断、5分钟保守回退、休市边界、价格公式、十倍杠杆与全量资金复盘口径均已存在，本变更只组合和复用这些能力。

## Goals / Non-Goals

**Goals:**

- 让一个60分钟回调事件以有序的首轮、第二轮结构返回结果，并严格限制最多两轮。
- 复用同一套范围、入场、止损、止盈和出场计算，避免为第二轮复制交易公式。
- 让图表同时保留两轮结果，同时保证每轮计划线只绘制到本轮终点。
- 让盈亏复盘把每个真正入场的轮次展开成独立交易，并继续使用现有按时间事件递推资金的机制。
- 保持60分钟点击后的紧凑视口和自动缩放行为不受完整生命周期长度影响。

**Non-Goals:**

- 不支持第三轮、第四轮或用户可配置的轮次数量。
- 不新增首轮红框边界延长线，也不新增1分钟可见图表。
- 不改变红框、四分之一入场、止损、止盈、风险侧调整、分钟优先级或仓位公式。
- 不修改60分钟信号发现逻辑。

## Decisions

### 1. 使用有序轮次模型表达交易结果

领域层引入轮次级结果结构，由整体生命周期持有最多两个有序轮次。每个轮次独立保存：

- 轮次编号与触发K线；
- 本轮用于计算和绘线的5分钟K线范围；
- 方向反应红框、四分之一入场、止损、止盈；
- 风险侧触碰与实际出场；
- 本轮终点或未完成状态。

整体生命周期继续持有交易时段、入场截止时间、休市强制出场K线、整体分析K线和紧凑 `focusBars`。整体终点与轮次终点分开计算，首轮实际出场不再直接截断整体分析范围。

选择该结构是因为图表和盈亏复盘都需要遍历0至2笔结果。相比增加一整套 `secondReactionRange`、`secondQuarterSignal` 等平行字段，有序轮次可以直接复用计算和渲染流程，并减少首轮与第二轮行为漂移。

### 2. 抽取可复用的单轮构造流程

将现有首轮计算整理为“给定方向、起始K线、候选K线、截止时间和分钟数据，构造一个轮次”的内部流程。该流程继续调用现有范围、入场、止损、止盈和出场函数，不复制价格公式。

整体算法按以下顺序运行：

1. 使用原60分钟回调触发K线开始的交易时段数据构造首轮。
2. 只有首轮存在真正入场和实际出场时，才从首轮出场K线的下一根5分钟K线开始扫描。
3. 选择第一根满足首轮红框风险侧条件的K线作为二次触发；扫描不包含首轮出场K线。
4. 从二次触发K线开始调用相同的单轮构造流程，因此触发K线自然参与方向反应搜索和极值统计。
5. 一旦创建第二轮，不再扫描新的二次触发；第二轮实际出场后立即确定整体终点。

未找到二次触发、找到触发但未找到方向反应、形成红框但未入场等状态都保留到交易时段结束或当前数据末尾，不创建替代轮次。

### 3. 用索引边界保证时序和交易时段隔离

二次触发扫描使用首轮出场K线在同一 `candidateBars` 数组中的索引加一作为起点，并沿用原交易日期和日/夜盘过滤结果。所有起止位置均通过K线 `startMs` 映射回索引，不依据数组切片后的相对时间猜测。

该选择明确保证：

- 首轮出场K线不会兼任二次触发；
- 第二轮不会跨交易日期或跨日夜盘；
- 第二轮仍受14:45/22:45入场截止与14:40-14:45、22:40-22:45强制出场规则约束；
- 数据末尾不会补造触发、反应、入场或出场。

### 4. 图表按轮次使用独立绘制层

5分钟图表选择状态携带有序轮次列表。绿色动态回调线和方向观察标记使用整体 `analysisBars`；每轮红框、白色入场线、黄色止损线和亮蓝色止盈线使用该轮自己的范围和终点。

由于最多两轮，渲染器为两个轮次维护稳定的覆盖层与计划线系列，并在轮次不存在时清空对应层。采用独立系列而不是把两段数据拼进同一折线，可以避免图表库跨越首轮出场至第二轮起点错误连线，也便于分别验证终点和自动缩放属性。

所有轮次相关 marker id 和诊断属性包含轮次编号。二次触发标记使用中性灰色文字“二次触发”，多头置于K线下方、空头置于K线上方；不创建边界参考线。切换60分钟事件、数据集、回到最新或清除选择时同时清空两个轮次的覆盖层、系列和标记。

### 5. 盈亏复盘将轮次展开为交易事件

盈亏复盘不再假设每个60分钟候选只有一笔交易，而是遍历生命周期内所有存在真正入场的轮次：

- 有实际出场的轮次生成完整的入场与出场回放事件；
- 已入场但未出场的轮次生成未完成交易；
- 只有触发、红框或计划线但未真正入场的轮次不生成交易。

交易id加入轮次编号以保持唯一。现有全局事件排序、入场时按可用资金计算仓位、出场时实现盈亏和资金曲线统计继续使用。第二轮入场必然晚于同一事件的首轮出场，因此现有时间序列会自然让第二笔仓位使用包含第一笔结果的资金；不同60分钟事件之间的重叠交易仍沿用现有独立回放语义。

### 6. 测试分层覆盖状态转换和可见结果

领域测试覆盖多空镜像、等值触发、出场K线排除、触发K线自身成为反应K线、包含式极值、第二轮锁定、截止时间、数据末尾和禁止第三轮。盈亏测试覆盖同一60分钟事件两笔交易的资金递推、统计计数和第二笔未完成状态。

渲染烟雾测试验证两组红框与计划线、灰色“二次触发”位置、首轮线段终点、第二轮线段终点、切换清理和无边界延长线。所有Electron与EXE自动化测试继续通过 `tests/electron-test-launch.mjs` 或 `--test-window-offscreen` 离屏启动，并验证窗口不与任一显示器相交。

### 7. 方向反应使用至少2个tick的实体门槛

首轮和第二轮继续共用 `entryReactionRange`。该函数接收当前标的tick，并只把多头 `close - open >= 2 × tick` 或空头 `open - close >= 2 × tick` 的第一根5分钟K线认定为方向反应。

十字K线、反方向K线以及只有1个tick的同方向K线都不能结束搜索，但仍位于触发K线至最终方向反应K线的包含区间内，因此继续参与多头最低价或空头最高价统计。门槛放在共享函数中，保证首轮、二次触发K线自身和第二轮后续K线使用同一口径。

## Risks / Trade-offs

- [整体生命周期与轮次终点混淆] → 在领域返回值中明确区分整体分析范围和每轮绘线范围，测试首轮出场后整体仍继续但首轮线已停止。
- [复制首轮逻辑导致两轮公式不一致] → 第二轮调用同一单轮构造流程和既有价格函数，只改变起始K线与触发来源。
- [两轮图形互相连接或覆盖] → 每轮使用独立且带轮次键的覆盖层和线系列，marker id 同样包含轮次编号。
- [盈亏交易id冲突或资金顺序错误] → id加入轮次编号，并继续统一按入场/出场事件时间排序；补充首轮出场后第二轮入场的资金断言。
- [当前工作区已有十倍杠杆相关未提交修改] → 实现时在现有 `profit-loss-review.ts` 基础上只扩展轮次展开，不回退或重写当前仓位公式。
- [长生命周期扩大初始视口] → `focusBars` 继续只取原触发附近的紧凑范围，完整 `analysisBars` 仅用于计算、平移后的绘制和标记。
- [1个tick K线被跳过后错误丢失区间极值] → 只延后方向反应索引，不过滤原K线数组；红框极值仍对触发至合格反应K线的完整切片计算。

## Migration Plan

1. 先扩展领域生命周期结构并以单元测试锁定两轮状态转换，同时保持既有价格函数结果不变。
2. 将图表选择、覆盖层、计划线和标记迁移为按轮次渲染，验证首轮行为回归与第二轮可见结果。
3. 将盈亏复盘改为展开所有真正入场轮次，保留当前资金、十倍杠杆及事件排序实现。
4. 更新入场规则文档和应用内规则说明。
5. 运行领域、盈亏、构建和离屏GUI测试；若回滚，只需恢复单轮生命周期消费者，不涉及持久化数据迁移。
