## Context

参见 `proposal.md` 的 Why。当前 `entryReactionRangeInHistory()` 在候选 K 线通过最小实体和方向侧影线规则后，如果命中连续反向 K 线阈值，只执行 `continue`，因此同一轮搜索会跳到更晚的候选。`entryLifecycle()` 又把结果直接组织为最多两个 `EntryLifecycleAttempt`，第二轮只会在第一轮真正入场并实际出场后启动。

现有渲染层只预建两个红框覆盖物并按正式轮次索引，盈亏复盘则只遍历 `lifecycle.attempts`。本变更需要在不改变正式两轮交易模型、参数存储、止盈止损公式和复盘资金公式的前提下，增加数量不受两轮上限约束的“反向动能放弃”观察记录，并保证所有搜索都受同一交易时段和数据末尾约束。

## Goals / Non-Goals

**Goals:**

- 将方向反应搜索结果明确区分为正式通过、反向动能放弃和未找到三种结果。
- 让同一个正式机会可以经历任意多次“放弃、风险侧再触发、重新搜索”，且正式机会编号不增加。
- 保存全部历史放弃红框和标记，同时只使用最新放弃红框的风险侧边界等待下一次重启。
- 复用既有正式轮次的入场、止盈、止损、休市离场和一分钟优先判定。
- 让领域结果、图表覆盖物、规则说明和盈亏复盘对放弃形态采用同一口径。

**Non-Goals:**

- 不修改“连续反向 K 线数量”的取值范围、默认值、持久化和十字星计数规则。
- 不修改最小入场 K 线浮动、2 倍与 3 倍影线、入场百分比、止盈止损或休市参数的计算。
- 不增加第三次正式交易机会，也不改变第一轮实际出场后启动第二轮的既有条件。
- 不为放弃形态绘制入场线、止损线、止盈线或生成模拟成交。
- 不新增行情数据、IPC、持久化 schema 或远端接口。

## Decisions

### 1. 使用可辨识联合类型表达方向反应搜索结果

将当前只返回 `EntryReactionRange | undefined` 的内部搜索拆为三类结果：

```ts
type EntryReactionSearchResult =
  | { kind: 'accepted'; range: EntryReactionRange }
  | { kind: 'abandoned-opposite-momentum'; setup: EntryAbandonedSetup }
  | { kind: 'not-found' };

interface EntryAbandonedSetup {
  triggerBar: Bar;
  candidateBar: Bar;
  reactionRange: EntryReactionRange;
  reason: 'opposite-momentum';
}
```

搜索仍先检查最小实体和方向侧影线。方向侧影线达到 3 倍时继续跳过并搜索下一根；候选通过影线过滤后才检查连续反向 K 线。命中阈值时立即返回 `abandoned-opposite-momentum`，不得继续扫描同一形态中的后续候选。

放弃红框与正式红框使用同一个 `EntryReactionRange` 几何结构，确保多头上沿、空头下沿以及从触发 K 线到候选 K 线的风险侧极值只有一套算法。放弃记录虽然携带该结构的 `pricingMode`，但不会调用入场、止损、止盈或实际出场计算。

替代方案是在生命周期函数外部先找候选、再重复计算红框，但会让正式和放弃形态的边界算法产生两套实现；继续用 `undefined` 或布尔值也无法携带候选位置与红框，因此不采用。

### 2. 放弃记录独立于正式 `attempts`

在 `EntryLifecycle` 增加 `abandonedSetups: EntryAbandonedSetup[]`，正式 `attempts` 继续只承载编号为 1 或 2 的正式机会。每次命中反向动能规则时只追加一条放弃记录，不创建 `EntryLifecycleAttempt`，也不递增正式机会编号。

第一轮形成前可以有任意条放弃记录；第一轮实际出场并启动第二轮后，第二轮形成前也可以有任意条放弃记录。第一轮和第二轮的兼容别名仍只指向第一条正式 `attempt`，不得指向放弃记录。

选择独立集合而不是给 `EntryLifecycleAttempt` 增加 `abandoned` 状态，是因为正式轮次编号、盈亏复盘和大量现有调用方都把 `attempts` 视为可入场计划。混入放弃记录容易错误消耗两轮上限或生成未完成交易。

### 3. 以单调向前的状态循环驱动同一正式机会

生命周期针对当前正式机会维护：

- `formalAttemptNumber`：当前仍待形成的正式机会编号；
- `searchStartIndex`：本次形态触发 K 线索引；
- `latestBoundary`：最近一条放弃记录或上一笔正式交易的风险侧边界；
- `resumeFromIndex`：允许查找下一次边界触发的最早索引。

状态推进如下：

```text
search-formal-shape
        |
        | accepted
        v
build-formal-attempt --> wait for true entry / exit
        |                         |
        | abandoned               | first formal exit
        v                         v
record-abandonment        wait-second-trigger
        |
        v
wait-latest-abandoned-boundary
        |
        | first touch/cross
        v
search-formal-shape (same formal number)
```

放弃候选自身不得兼作重启触发。系统从它的下一根实际 5 分钟 K 线开始，按多头 `low <= range.low`、空头 `high >= range.high` 找第一根触碰或穿越风险侧边界的 K 线，并让该 K 线作为新触发 K 线参与后续方向反应和新红框极值计算。

若新搜索再次被放弃，记录会追加到历史集合，并用这条最新记录替换 `latestBoundary`。更早红框仅保留展示，不再参与触发判断。只有正式形态实际入场并出场后，正式机会编号才按既有流程从 1 推进到 2；第二轮出场后立即结束，不再进入任何重启状态。

所有状态转换都使用数组索引并强制向后推进：放弃后从 `candidateIndex + 1` 查找，正式出场后从 `exitIndex + 1` 查找。任何找不到候选、找不到边界触发、到达交易时段末尾或数据末尾的情况都结束循环，避免同一根 K 线重复消费或无限循环。

替代方案是递归调用现有 `buildEntryLifecycleAttempt()`，但连续放弃次数没有上限，递归深度和状态归属更难验证；显式循环更容易证明索引单调递增。

### 4. 正式计划构建与放弃搜索解耦

把“找到反应形态”和“构建入场、止损、止盈与出场计划”分成两个阶段。搜索结果为 `accepted` 时才调用现有正式计划计算；结果为 `abandoned-opposite-momentum` 时只保存红框和标记；结果为 `not-found` 时按当前交易时段或数据边界结束。

正式机会一旦接受某个方向反应红框，后续是否真正触碰入场线、是否休市、是否到达数据末尾仍完全沿用当前逻辑。也就是说，本变更只改变连续反向动能命中时的分支，不把其他未入场情形自动变成可重复重启的放弃形态。

### 5. 图表覆盖物改为按稳定键动态协调

5 分钟图表不再只预建两个固定红框。渲染层从 `attempts` 与 `abandonedSetups` 生成统一描述列表，每个描述包含稳定键、红框范围和类别：

- 正式红框键使用 `formal-1`、`formal-2`；
- 放弃红框键使用候选 K 线时间，例如 `abandoned-{candidateStartMs}`；
- 类别用于设置测试属性和必要的视觉语义，红框本身继续沿用现有范围样式。

图表类通过 `Map<string, HTMLElement>` 创建、更新、隐藏和删除覆盖物，而不是依靠数组索引。每次选择刷新、缩放、滚动或尺寸变化时按当前描述重绘；切换事件、数据集、普通联动、回到最新或清除选择时移除不再存在的全部动态覆盖物。

标记层为每个放弃候选 K 线增加中性文字“反向动能放弃”。该标记与真正入场、风险侧触碰、二次触发、止盈止损和休市出场使用不同文案及中性色；放弃记录不产生任何计划线 series。

替代方案是预建一个较大的固定覆盖物数组，但放弃次数没有上限，固定容量必然截断历史或浪费节点，因此不采用。

### 6. 盈亏复盘继续只消费正式交易

`profit-loss-review.ts` 继续只遍历 `lifecycle.attempts`，并继续要求存在真正 `entryBar` 才能生成已完成或未完成交易。`abandonedSetups` 不进入交易 ID、手数计算、资金曲线或任何统计计数。

虽然独立集合已经从结构上避免误计，本变更仍增加明确测试：只有放弃形态时资金和统计不变；多次放弃后完成第一笔或两笔正式交易时，只统计正式交易；放弃发生在两笔正式交易之间时，第二笔继续使用第一笔出场后的资金。

### 7. 规则文本和可测试诊断同步领域语义

更新完整入场规则、外部规则文档和“五分钟 K 线识别”说明，把“跳过当前候选并继续寻找”改为“结束当前形态、保留放弃红框、等待风险侧再次触发后以同一正式机会重新搜索”。说明同时覆盖参数为 0、多空镜像、触发 K 线参与新搜索、历史红框保留、最新边界生效以及最多两次正式机会。

渲染诊断属性增加放弃记录数量、候选时间和风险边界，方便领域测试之外的渲染与离屏 GUI 测试确认动态覆盖物没有遗漏或残留。

## Risks / Trade-offs

- [连续放弃导致生命周期扫描成本增加] -> 每次搜索或等待都从严格递增的索引继续，单个 60 分钟事件对交易时段内 K 线保持线性级别推进，避免从头反复扫描。
- [复用 `EntryReactionRange` 暴露无实际用途的 `pricingMode`] -> 放弃记录只允许渲染读取几何字段，类型和测试禁止其进入计划信号计算；复用可确保红框算法一致。
- [动态 DOM 覆盖物在切换或缩放后残留] -> 使用稳定键协调并在所有现有清理路径统一删除，多次选择切换和缩放纳入渲染测试。
- [正式轮次与放弃记录的时间顺序被两个数组拆开] -> 每条记录保留触发和候选时间；需要展示时按时间生成描述列表，不依赖数组拼接顺序表达业务先后。
- [数据末尾只有放弃记录时可能被误报为未完成交易] -> 盈亏层只认正式 `attempt` 的真实 `entryBar`，并增加资金与计数保持不变的回归测试。
- [规则关闭时行为意外变化] -> `oppositeCandleCount = 0` 直接绕过放弃分支，并用与变更前相同的候选、计划和出场断言锁定兼容性。

## Migration Plan

1. 扩展领域类型与方向反应搜索结果，先用单元测试锁定正式通过、放弃和未找到三类结果。
2. 将 `entryLifecycle()` 改为索引单调推进的循环，接入放弃记录、最新边界重启和最多两次正式机会。
3. 扩展盈亏复盘测试，确认放弃记录不会形成交易或改变资金。
4. 将 5 分钟图表红框和标记改为动态协调，补充切换、缩放和清理测试。
5. 更新应用内及外部规则说明，运行规则一致性、类型检查、单元测试、构建和遵守离屏窗口约束的 Electron 测试。
6. 本变更没有持久化数据迁移。若需要回滚，恢复原搜索分支和固定正式红框渲染即可；已有用户参数与行情快照无需转换。
