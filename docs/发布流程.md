# MoneyComing 发布流程

MoneyComing 只发布 Windows x64 NSIS 安装版。每次提交并推送到 `main` 后，GitHub Actions 自动生成更高的稳定版本、标签和正式 Release，不生成或上传 ZIP 便携包。

## 发布前

1. 更新 README、使用说明和必要的版本说明，提交全部准备发布的代码。
2. 在 Windows、Node.js 22 环境执行质量门禁：

```powershell
npm ci
npm run typecheck
npm test
npm run test:app
npm run test:update
npm run package
npm run verify:release
npm run verify:security -- --require-artifacts
npm run test:installer
```

## 创建发布

确认工作区提交完成后推送 `main`：

```powershell
git push origin main
```

`Publish Windows Release` 工作流会根据工作流运行序号计算一个高于当前 Release 的稳定版本，并依次执行版本校验、测试、NSIS 构建、产物与凭据扫描、安装/启动/卸载冒烟测试，然后自动创建标签和包含以下资源的 GitHub Release：

- `MoneyComing-Setup-<version>-x64.exe`
- `MoneyComing-Setup-<version>-x64.exe.blockmap`
- `latest.yml`

工作流先上传完整的草稿资源，再公开 Release。匿名读取验收失败时会删除本次不完整 Release 和自动标签，之前的稳定 Release 保持不变。构建或测试失败时不会向已安装用户发布更新；修复后再次推送 `main` 即可生成下一个版本。

## 发布后

1. 在未登录 GitHub 的浏览器窗口打开新 Release，确认安装包、blockmap 和 `latest.yml` 均可下载，且没有 ZIP。
2. 首个更新版要求旧 ZIP 用户手动安装 NSIS；记录迁移结果。
3. 再发布一个更高补丁版本，从已安装的前一版本验证“检查更新 → 立即下载 → 重启安装 → 版本变化”，并保存版本、下载进度、安装结果和失败恢复记录。
4. 若新版本存在严重问题，撤下该 Release 并发布更高修复版本，不复用旧标签。

## 可选代码签名

仓库可配置 `WINDOWS_CSC_LINK` 和 `WINDOWS_CSC_KEY_PASSWORD` Actions secrets。存在证书时，发布工作流要求安装包与 `MoneyComing.exe` 的 Authenticode 状态为 `Valid`；未配置证书时仍可构建，但发布说明和用户文档必须保留 SmartScreen“未知发布者”提示。
